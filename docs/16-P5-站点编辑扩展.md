# 16 · P5 站点编辑扩展 (2026-06-05)

> 在 P5 站点管理基础上扩展: 改 slug 字段 + 修复保存后不关窗 + 修 3 个 lazy IO 引起的 500

## 范围

### 新功能: 改 slug

**后端**
- `app/schemas/site.py` — `SiteUpdate` 加 `slug: str | None` + SLUG_PATTERN validator
- `app/api/v1/sites.py`
  - `update_site` 改 slug 时先校验唯一性 (DB 兜底, 提前抛 Conflict 40901)
  - 改 slug 后调 `rebuild_sites_map(db)` 重写 nginx sites.map
  - 容错: rebuild 失败 log warning 不抛 (与 startup 一致)

**前端**
- `src/api/sites.ts` — `SiteUpdatePayload.slug?: string`
- `src/pages/Sites.tsx` — `EditDialog` 加 slug 输入
  - 客户端校验: 同步后端 SLUG_PATTERN
  - 改时才有 amber 警告 ("会重建 nginx 路由")
  - 不变不传 (payload.exclude_unset)

### Bug 修复 (3 个)

#### Bug 1: 保存修改不关窗
- 文件: `frontend/src/pages/Sites.tsx:330`
- 症状: 点 "保存修改" 后 toast 成功但 dialog 还在
- 原因: `updateMut.onSuccess` 漏 `onClose()` (CreateDialog 是有的, EditDialog 漏了)
- 修法: onSuccess 末尾加 `onClose()`

#### Bug 2: `get_site` 500 (Pydantic lazy IO)
- 文件: `backend/app/api/v1/sites.py` `get_site` + `update_site` + `create_site`
- 症状: `ValidationError: domains Error extracting attribute MissingGreenlet`
- 原因: SiteRead 加 `domains: list[SiteDomainRead]` 后, Pydantic 序列化时访问 `site.domains` 触发 lazy IO (async session 里不允许同步访问)
- 修法: 显式 `selectinload(Site.domains.and_(SiteDomain.deleted_at.is_(None)))` + 重新查
- 同时改 `create_site` + `update_site` (3 处都炸过)

#### Bug 3: `add_domain` / `remove_domain` 500 (nginx map 隐式 IO)
- 文件: `backend/app/core/nginx.py` `_format_map` + `rebuild_sites_map`
- 症状: 添加/删除域名 500, 错在 `rebuild_sites_map` 内部
- 原因: `_format_map` 访问 `d.site.slug` 触发 lazy load (在 async 函数里走同步 IO)
- 修法: `rebuild_sites_map` 直接 `(d, slug)` 元组传给 `_format_map`, 函数签名同步
- 同时给 `add_domain` / `remove_domain` 的 `rebuild_sites_map` 调用加 try/except (P5 容错)

## 风险

- **改 slug 不迁移发布文件**: `SITES_DATA_DIR/{slug}/` 路径保留旧 slug, 改了 slug 后发布的页面仍按旧路径找, 可能 404。MVP 提示用户重新发布, **V2 改**加发布文件迁移
- **改 slug 中间人引用**: 静态发布的 HTML 里有旧 slug 链接, 改完不会自动更新。V2 改
- **不并发控制**: 两个 admin 同时改同一站 slug, 一个会冲突 40901 (DB 兜底)

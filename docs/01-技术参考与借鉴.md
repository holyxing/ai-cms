## 逐家学习清单

### 1. Strapi ⭐⭐⭐⭐⭐

**学什么**：
- **Content-Type Builder** —— 在后台可视化定义模型（字段、关系、类型）
- **插件市场** —— 通过 npm 包扩展（i18n、seo、graphql、audit-log）
- **RBAC** —— Provider 模式（内置 + 自定义）
- **Media Library** —— 可配置 provider（本地 / S3 / Cloudinary）
- **Webhooks** —— 内容变更触发外部动作

**怎么用**：
- 我们的 `taxonomies` / `contents` / `media` 模块借鉴 Content-Type Builder 的体验
- 我们的 AI Agent 用"插件式"注册（每加一个能力 = 注册一个 Agent task）
- 媒体库默认 MinIO，预留 S3 适配

---

### 2. Payload CMS ⭐⭐⭐⭐

**学什么**：
- **TypeScript-first** —— 模型即代码，类型全自动
- **本地优先** —— SQLite 默认，能跑在离线环境
- **Lexical 富文本** —— Meta 出品，性能比 Tiptap 略好
- **Hooks** —— beforeChange / afterChange 拦截
- **Access control** —— 字段级函数式权限

**怎么用**：
- 我们用 Pydantic v2 + SQLAlchemy 2.0（Mapped 类型）达到"模型即类型"
- 权限用 FastAPI Depends + 装饰器，参考 Payload 的函数式风格
- Tiptap 仍选，因为我们已有生态基础；Lexical 留作备选

---

### 3. FormCms ⭐⭐⭐⭐

**学什么**：
- **AI Agent 模块** —— 把"AI 改内容"作为一等公民集成
- **Document Database 思路** —— 字段可动态扩展
- **组件分层** —— Server / AdminPanel / Examples 分仓
- **Message-based Worker** —— 异步任务用消息队列

**怎么用**：
- 直接照搬它的"AI Agent" 概念到我们的 `backend/app/agents/`
- Worker 用 Celery（更 Pythonic）或直接看它的 message-based 思路
- 我们的目录里拆出 `agents/tasks/` 子目录

---

### 4. Sveltia CMS ⭐⭐⭐

**学什么**：
- **极简 UX** —— 登录到发布 3 步
- **i18n 优先** —— 国际化从第一天就考虑
- **Git-based 同步** —— 内容推到 Git，可被外部工具消费

**怎么用**：
- 后台导航参考它的"少即是多"
- 国际化：MVP 不做，但**目录结构和字段预留**（i18n JSONB）
- Git 同步：作为高级选项，V2 实现

---

### 5. Sanity ⭐⭐⭐⭐⭐

**学什么**：
- **Portable Text** —— 块级内容 JSON schema（我们用 Tiptap JSON 等价物）
- **GROQ 查询语言** —— 用声明式语法查嵌套数据
- **Real-time Studio** —— 多用户实时协作（V2）
- **Custom Blocks** —— 自定义 block 类型有强约束
- **Image Pipeline** —— 上传时自动生成多尺寸 + hotspot

**怎么用**：
- 我们的 `contents.blocks` 字段直接用 Tiptap JSON
- 不学 GROQ（过度工程），用 Pydantic 验证就够
- 图片处理：MVP 用浏览器端多尺寸生成（Canvas），V2 上 Pillow worker
- 自定义 block：参考 Sanity 的 schema 思路，定义每种 block 的 JSON schema

---

### 6. Builder.io ⭐⭐⭐⭐⭐

**学什么**：
- **设计 tokens** —— "样式"被结构化为可编辑变量
- **拖拽 + 选中** —— 选中任意元素直接改它的 token
- **AI 文本改写** —— 选中段落调用 AI
- **可视化 + 代码双视图** —— 设计师和工程师都能用
- **导出干净代码** —— 不用 Builder 的运行时也能跑

**怎么用**：
- 我们的 `current_theme.tokens` 完全借鉴这个思路
- AI 调样式 = 改 token，不改源码
- 我们的"选中段落 AI 改写"直接抄 Builder 的 UX
- 拖拽编辑 MVP 不做，但**预留接口**

---

### 7. Directus ⭐⭐⭐

**学什么**：
- **数据库即内容** —— 不写迁移，直接在后台建表
- **REST/GraphQL 自动生成** —— 不用手写 CRUD
- **细粒度权限** —— 字段级 + 角色级
- **Flows** —— 可视化工作流（事件 + 条件 + 动作）

**怎么用**：
- "数据库即内容" 暂不学（会增加复杂度），但 `taxonomies` / `contents` 的元数据可以借鉴
- FastAPI 的自动 CRUD 用 `fastapi-crudrouter` 或手写（更可控）
- Flows 概念 → 我们做成 Agent 编排（更智能）

---

### 8. Webflow ⭐⭐⭐⭐

**学什么**：
- **样式与结构分离** —— 改样式不动 DOM
- **设计 → 代码** —— 设计师产出 → 工程师导出 React
- **CMS 字段** —— 在设计器里直接绑内容字段
- **响应式断点** —— 同页面不同断点独立设计

**怎么用**：
- 我们的"主题 + 组件"思路来自这里
- 断点设计：token.breakpoint 已经有了
- "CMS 字段绑定"：block 有个 `dataSource` 字段，从内容/分类/媒体里拉数据

---

### 9. WordPress / Gutenberg ⭐⭐⭐⭐

**学什么**：
- **Block 编辑器事实标准** —— 全网最普及
- **Block 模式** —— 预制组合（如"带图卡片"）
- **媒体库 UX** —— 上传/筛选/编辑
- **角色生态** —— 站长/编辑/作者/订阅者
- **生态插件** —— 反过来：用户能装第三方 block

**怎么用**：
- RBAC 角色直接借用 WP 的 5 级体系，我们简化到 4 级
- "Block 模式" = 我们的 `theme.components` 里预制组合
- 第三方 block：MVP 不做插件机制，V2 用 Python 包

---

### 10. Notion / 飞书 ⭐⭐⭐⭐

**学什么**：
- **`/` 命令** —— 斜杠插入 block
- **拖拽手柄** —— 左侧 hover 出现
- **AI 块内联** —— 选中文字浮出 AI 操作
- **模板库** —— 空白页给模板起步

**怎么用**：
- Tiptap 配 FloatingMenu / BubbleMenu 实现 `/` 和选中 AI
- 模板库：`templates/` 目录，存 JSON 模板，可一键套用

## 我们产品的差异化定位

吸收了上面所有优点后，**我们独特在哪**：

| 维度 | 现有 CMS | **我们 AI-CMS** |
|---|---|---|
| 内容建模 | ✅ Strapi/Directus | ✅ + **AI 帮你配字段** |
| 编辑体验 | ✅ Sanity/Builder | ✅ + **AI 侧栏全程在场** |
| 样式 | ✅ Webflow/Builder | ✅ + **AI 改 token，对话式调样式** |
| 静态发布 | ✅ Gatsby/Next SSG | ✅ + **AI 帮你审计发布质量** |
| 多站点 | ✅ WordPress Multisite | ✅ + **AI 帮你管多站点的统一性** |
| 反向导入 | ❌ | ✅ **从 HTML 反向提取主题**（V2） |
| 中文优化 | ⚠️ 多数英文优先 | ✅ **中文 AI/中文 SEO 优先** |
| 部署 | ⚠️ 多数复杂 | ✅ **单机 docker compose 一键** |

**一句话：**
> 别人是"工具 + AI 插件"；我们是"AI 是一等公民，每个动作都有 AI 在场"。

## 技术栈最终选型（确认版）

| 层 | 选型 | 理由 |
|---|---|---|
| **后台前端** | React 18 + Vite + TypeScript + Tailwind + Zustand + TanStack Query | 现代、稳、好招人 |
| **富文本** | Tiptap 2 + 自研 AI Extension | 生态最大、可扩展 |
| **后台 UI 库** | shadcn/ui（基于 Radix）+ Tailwind | 漂亮、可改、好控制 |
| **后端** | FastAPI + Pydantic v2 + SQLAlchemy 2.0 + Alembic | 你定的，标准栈 |
| **后台认证** | FastAPI-Users 或自撸（JWT + Refresh） | 看复杂度 |
| **任务队列** | Celery + Redis | 成熟 |
| **数据库** | PostgreSQL 16 + JSONB | 你定的 |
| **媒体存储** | MinIO（S3 兼容） | 私有部署友好 |
| **静态生成器** | Astro 4+ | 内容站最优解 |
| **AI 抽象** | litellm（统一 OpenAI/Anthropic/Ollama 接口）| 省事，主流 |
| **本地 LLM** | Ollama | 最简单 |
| **反代/静态** | Nginx | 标配 |
| **部署** | Docker Compose | 单机 |
| **监控（V2）** | Prometheus + Grafana | 后期 |

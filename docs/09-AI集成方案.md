# 09 · AI 集成方案（P3 必读）

> P3 启动前必读。AI 架构、状态机、限流、成本控制、可解释性。

## 0. 选型决策

**不直接使用 LangGraph 框架**——取其**状态机思想**，**自建简化版**。

| 方案 | 适合 | 评估 |
|---|---|---|
| LangGraph | 复杂多步工作流 | API 不稳定, 中文文档少, 0.1+ 还在快速迭代, **生产风险高** |
| CrewAI | 多 Agent 协作 | 抽象层太厚, 调试困难 |
| **自建 (FastAPI + Celery + 状态字段)** | 简单任务流 | **推荐** — 灵活、可控、易调试 |

**自建核心**：每个 AI 任务 = Celery task + PostgreSQL 状态字段 + SSE 流式输出。

  theme_version_id BIGINT REFERENCES theme_versions(id),
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ai_runs_user ON ai_runs(user_id, created_at DESC);
CREATE INDEX idx_ai_runs_status ON ai_runs(status) WHERE status IN ('pending', 'running');

CREATE TABLE ai_run_steps (

## 3. LLM 适配层（**所有提供商走同一接口**）

### 3.1 统一接口

```python
# backend/app/services/llm/base.py
from abc import ABC, abstractmethod
from typing import AsyncIterator

class LLMProvider(ABC):
    @abstractmethod
    async def generate(
        self, messages: list[dict], model: str, **kwargs
    ) -> 'LLMResponse':
        """非流式"""

    @abstractmethod
    async def stream(
        self, messages: list[dict], model: str, **kwargs
    ) -> AsyncIterator['LLMChunk']:
        """流式"""

    @abstractmethod
    def count_tokens(self, text: str, model: str) -> int:
        """估算 token 数 (用于成本预估)"""

    @abstractmethod
    def get_cost(self, prompt_tokens: int, completion_tokens: int, model: str) -> Decimal:
        """计算成本 (USD)"""


class LLMResponse:
    content: str
    prompt_tokens: int
    completion_tokens: int
    model: str
    finish_reason: str


class LLMChunk:
    delta: str                # 增量文本
    finish_reason: str | None
```

### 3.4 minimax (MiniMax) Provider 接入 (P3-minimax, 2026-06-06)

**背景**：用户要求 "大模型不要先接入本地模型，而是用 minimax 接入"

**协议**：OpenAI 兼容 (`/v1/chat/completions`), 走 `app/services/llm/openai.py:OpenAIProvider`

**接入方式**：
1. `deploy/.env` 加 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL=https://api.minimaxi.com/v1` / `MINIMAX_DEFAULT_MODEL=abab6.5s-chat`
2. `AI_DEFAULT_PROVIDER=minimax`
3. 重建镜像: `docker compose -f deploy/docker-compose.yml build api worker && up -d api worker`
4. 调用链路: user 没 is_default provider → worker 读 `settings.AI_DEFAULT_PROVIDER` 建虚拟 SimpleNamespace → factory 用 `settings.MINIMAX_API_KEY` 走 OpenAI 协议调 minimax

**成本**：`abab6.5s-chat` ~$0.000001/输入 token + $0.000008/输出 token (USD)

**限制**：
- minimax **不发 `[DONE]` sentinel** (P3.1.2 修复) — usage 帧直接 yield 终结
- minimax **进 `<think>...` 内部思考** — 用户面输出在 `</think>` 之后

**E2E 验证** (`POST /ai/tasks/rewrite/start` polish 操作):
- `POST https://api.minimaxi.com/v1/chat/completions "HTTP/1.1 200 OK"`
- 1.1 秒, 90 tokens, 45 字符输出
- cost $0.000720
- 示例输出: "本文专为包含关键词"unicornsandrainbows"而精心构思, 并融入了独家密语。"

**踩过的坑**：
1. `Mock Provider is_default=True` 拦截了 minimax fallback → 删 mock + worker 检测 `api_key_encrypted` 空时也走 settings
2. Docker compose **不挂载 backend 代码**, host 改完必须 `build` 重建镜像
3. `from loguru import logger` 在函数里导致 `UnboundLocalError` (顶层已有 logger)
4. `factory._provider_cache` 缓存失败的 ollama 实例, P3.0 简化去掉
5. minimax API 可能返 `choices=[]` (usage 帧) — P3.1.1 防御已加

## 4. 6 个 AI 功能实现

### 4.1 AI 起稿 (draft)

**输入**：主题 + 大纲 + 字数
**输出**：Markdown 格式文章

**实现**：
```python
async def ai_draft(user, input):
    run = await create_ai_run(user, task_type="draft", input=input)
    await run_step(run, "validate", validate_draft_input)  # 验证输入
    await run_step(run, "generate", generate_draft)        # LLM 生成 (流式)
    await run_step(run, "sanitize", sanitize_html)          # XSS 清理
    await run_step(run, "save", save_draft_to_content)      # 写入 content_versions
    return run
```

**难点**：
- 上下文长（>8K 字）→ **分段生成 + 滑窗**
  - 先生成大纲（500 字）
  - 再分章节生成（每章 800-1500 字）
  - 最后合并
- 流式输出：每 chunk 写 `ai_run_steps.output` + SSE 推前端

### 4.2 AI 改写 (rewrite)

**输入**：原文 + 操作（改写/扩写/缩写/翻译）+ 目标语言
**输出**：改后文本

**实现**：
- 选中文本 → `POST /api/v1/ai/rewrite`
- 流式返回（打字机效果）
- 用户可"接受"/"拒绝"
  - 接受 → 替换原文本
  - 拒绝 → 回滚

**回滚机制**（之前漏的）：
- AI 改写前**先存原文本**到 `ai_runs.input.original_text`
- 拒绝时前端恢复原文本

### 4.3 AI 配图 (image)

**输入**：段落文本 + 风格
**输出**：图片 URL

**实现**：
- DALL-E 3 / Stable Diffusion / 国产模型
- 慢（10-30s）→ 必须**轮询 + 进度条**
- 生成成功后：
  1. 下载到 MinIO
  2. 创建 `media` 记录
  3. 返回 URL 给前端

**难点**：
- API 慢，前端不能干等
- 必须有**取消按钮**（用户不想等了）
- 失败重试不能扣费

### 4.4 AI 改主题 (theme) ⭐

**输入**：自然语言描述（如"改成深色，蓝色更亮"）
**输出**：新主题 tokens

**实现**：
```python
async def ai_modify_theme(user, site_id, prompt):
    # 1. 加载当前 tokens + tokens_schema (白名单)
    current_tokens = get_active_theme_tokens(site_id)
    schema = THEME_TOKENS_SCHEMA  # JSON Schema
    
    # 2. LLM 输出受 schema 约束 (function calling / JSON mode)
    new_tokens = await llm.generate_json(
        messages=[
            {"role": "system", "content": THEME_MODIFY_PROMPT},
            {"role": "user", "content": prompt},
        ],
        response_schema=schema,  # 强制 LLM 输出符合 schema
    )
    
    # 3. 二次校验: 任何字段不在 schema 内 → 拒绝
    validate_against_schema(new_tokens, schema)
    
    # 4. 创建新 theme_version (不覆盖!)
    new_version = create_theme_version(
        site_id, tokens=new_tokens, is_ai_generated=True, prompt=prompt
    )
    
    # 5. 前端预览: 切换到新 version, 用户确认后 is_active=true
```

**关键**：
- **不能改 HTML**！只改 tokens
- **白名单**用 JSON Schema 强制约束
- 用户可一键**回滚**（之前 version 还保留）

### 4.5 AI 审计 (audit)

**输入**：内容 ID

### 4.6 AI 智能问答 (RAG) — P3 后期/P4

**输入**：用户问题
**输出**：基于已发布内容的答案

**实现**：
- 内容发布时 → 切片 → embedding → 存 `content_embeddings` (pgvector)
- 用户提问 → embedding → 向量检索 top 5 → LLM 生成答案 + 引用

**pgvector 扩展**（P4）：
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE content_embeddings (
  content_id BIGINT,
  chunk_index INTEGER,
  chunk_text TEXT,
  embedding vector(1536),  -- text-embedding-3-small
  PRIMARY KEY (content_id, chunk_index)
);
CREATE INDEX ON content_embeddings USING ivfflat (embedding vector_cosine_ops);
```

## 5. 限流与成本控制（**重要**）

### 5.1 三层限流

| 层级 | 限制 | 触发 |
|---|---|---|
| L1 用户频次 | 每用户每分钟 10 次 | Redis 计数 |
| L2 并发数 | 每用户同时 3 个任务 | Celery 检查 |
| L3 成本 | 每用户每月预算 (默认 $10) | DB 统计 |

### 5.2 成本预估

**AI 起稿**前先**预估成本**：
```python
estimated_tokens = count_tokens(prompt + max_output)  # 假设输出 2000 字
estimated_cost = pricing.get_cost(estimated_tokens, model)

if user.monthly_used + estimated_cost > user.monthly_budget:
    raise BudgetExceeded("本月预算不足, 请充值或调低预算")
```

### 5.3 失败不扣费

- LLM 调用失败 → 不写 `ai_usage_daily`
- 用户中途取消 → 按**实际生成量**计费（更友好）

### 5.4 实时成本显示

前端 SSE 流中**每 chunk 显示**：
- "已消耗 $0.023 / 预估 $0.05"
- "剩余预算 $9.85"

## 6. 状态机实现（**自建，不用 LangGraph**）

### 6.1 每个任务是一系列 step

```python
# backend/app/services/ai/state_machine.py
class AIStateMachine:
    """简化版状态机"""

    STATES = {
        "draft": ["validate", "outline", "chapters", "merge", "sanitize", "save"],
        "rewrite": ["validate", "generate", "sanitize"],
        "theme": ["validate", "generate", "apply", "preview"],
        "audit": ["validate", "analyze", "score"],
        "image": ["validate", "generate", "download", "register"],
    }

    async def run(self, task_type: str, run_id: str):
        steps = self.STATES[task_type]
        for i, step_name in enumerate(steps):
            # 更新 ai_runs.current_step
            await update_run(run_id, current_step=step_name, steps_done=i, steps_total=len(steps))

            # 执行 step
            step_func = getattr(self, f"step_{task_type}_{step_name}")
            await run_step(run_id, i, step_name, step_func, run_id)
```

### 6.2 断点续传

- 每 step 完成立即**持久化**到 `ai_run_steps`
- 客户端刷新页面 → 看 `ai_runs.current_step` + `ai_run_steps.output` 恢复
- Celery 任务可重入（`task_acks_late=True` + `idempotency_key`）

### 6.3 SSE 推送

```python
# backend/app/api/v1/ai.py
@router.get("/runs/{run_id}/stream")
async def stream_run(run_id: UUID, user: User = Depends(get_user)):
    # 鉴权: run 属于 user

        ai_event_generator(run_id, user),
        media_type="text/event-stream"
    )
```

**前端**：
```tsx

  const chunk = JSON.parse(e.data);
  setOutput(prev => prev + chunk.delta);
  setCost(c => c + chunk.cost);
};
```

## 7. AI Key 加密

```python
# backend/app/services/ai/key_manager.py
from cryptography.fernet import Fernet
from app.core.config import settings

cipher = Fernet(settings.BACKEND_SECRET)  # BACKEND_SECRET 是 32 字节 base64

def encrypt_key(plaintext: str) -> bytes:
    return cipher.encrypt(plaintext.encode())

def decrypt_key(ciphertext: bytes) -> str:
    return cipher.decrypt(ciphertext).decode()
```

**调用**：
```python
key_row = db.query(APIKey).filter_by(user_id=user.id, provider="openai").first()
plaintext_key = decrypt_key(key_row.encrypted_key)
provider = LLMFactory.create("openai", api_key=plaintext_key)
```

## 9. 错误处理

| 错误 | 处理 |
|---|---|
| API Key 无效 | 401, 前端提示"Key 无效，请检查" |
| 余额不足 | 402, 前端提示"AI 服务余额不足" |
| 速率限制 (提供方) | 429, 自动重试 3 次 + 指数退避 |
| 内容超长 | 422, 提示用户缩短 |
| 网络中断 | Celery 重试, SSE 断线后**客户端可重连** |
| 内容违规 | 400, 提示"内容不合规" + 详情 |

**所有错误写 `ai_runs.error_message` + audit_logs**。

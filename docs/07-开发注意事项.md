## 2. 后端 / 部署（继承 P0）

| 坑 | 解决方案 |
|---|---|
| Docker Hub 不可达 | `docker.m.daocloud.io/library/{image}` |
| 端口冲突 | API 18888, Admin 18889, MinIO 9000-9001, Postgres 5432, Redis 6379 |
| Alembic 迁移 | 每次模型变更 = 新 migration 文件，**不删旧文件** |
| Celery 与 API 共享 | worker 容器挂载同一 `/app` |

### P1 新增注意
- **大文件上传**（>5MB） → 走 MinIO presigned URL 客户端直传，**不走 API**
- **图片处理**（Pillow） → 必须**异步**（Celery），同步会卡 API
- **CORS** → MinIO 容器需配置允许 `http://localhost` / `http://admin.*`
- **API 限流** → `slowapi`（P1 中期引入，发布前必须）
- **SQL 注入** → 一律 ORM，**不写原生 SQL**（除非 explain analyze）

### P2 新增注意
- **Astro 构建** 在独立容器 `node:25.8.1-alpine`，不与前端混
- **构建产物** 存到 `/data/sites/{site_id}/public/`，nginx 直接 serve
- **构建触发** Celery Beat，**不阻塞** API

### P3 新增注意
- **AI API Key** 必须**后端代理调用**（不暴露到前端）
- **AI Key 加密** Fernet（P3.1）
- **流式响应** SSE，**不是** WebSocket（nginx 友好）
- **AI 调用限流** 每用户每分钟 10 次

### P3.7+ 模板嵌套注意 (2026-06-10)
- **HY_TEMPLATE 必传 `code` 属性**: `<HY_TEMPLATE code="header-v1" />`，不是 `name` 不是 `id`
- **HY_SITE_MENU 必传 `_location` 属性**: `<HY_SITE_MENU _location="header" />` 或 `_location="footer"`，不传返空字符串 (后端 `_lookup_value` 返 "")
- **目标模板必须 `template_kind=partial`**: 不能引用普通 page 模板 (避免页套页死循环)
- **循环引用检测**: worker 走 `rendering_codes` set，发现环报 422 + 错误信息
- **前端 lint 维护**: `frontend/src/api/layouts.ts` 的 HY_TAGS 数组要跟后端 `layout_renderer._SAFE_TAGS` / `_SELF_CLOSING_TAGS` 同步。新加标签双端都要改
- **code 业务属性豁免**: HY_TEMPLATE 用 `code=`，不在 `_` 前缀白名单，但前端 `BUSINESS_ATTRS` 白名单豁免 (HTML 原生 `code` 不是合法属性, 业务上需要)
- **deploy 顺序**: 改 backend 后需 `docker compose restart api worker` (worker 缓存 Python 模块, uvicorn --reload 不带动)

### P3.7.2 模板 tab 重构踩点 (2026-06-10)
- **同名站点看 slug 不只看 name**: 霍因科技有 2 站, `hy-1780608182` (6/8 软删) + `hydata` (活). 查站时永远 `WHERE deleted_at IS NULL`
- **查 layout 用 INNER JOIN** (不是 LEFT JOIN) 过滤已删站点
- **侧栏 240px 不分左右**: 5 目录 + 列表的内嵌二级视图比"侧栏分左右" 体验好
- **Vite dev 端口 18889**: host 映射 `5173→5173` 但 host port 是 `18889` (看 deploy/.env `FRONTEND_PORT`)
- **API 端点格式**: 后端 `PUT /sites/{id}/template-scope-labels` 不是 PATCH (其他 site 端点用 PATCH, 记住按各文件装饰器看)

## 4. 数据库设计

### P0 已建
- `users` (id, email, hashed_password, name, is_super_admin, ...)

### P1 待建（按顺序）
- `sites` (id, slug, name, description, theme_id, created_at, updated_at, is_deleted)
- `site_members` (site_id, user_id, role: owner|editor|viewer)
- `taxonomies` (id, site_id, parent_id, name, slug, type: category|tag, path, order)
- `contents` (id, site_id, taxonomy_id, author_id, title, slug, status: draft|pending|published, ...)
- `content_versions` (id, content_id, version, title, body_json, body_html, body_text, author_id, created_at)
- `media` (id, site_id, uploader_id, filename, mime, size, width, height, url, md5, created_at)
- `themes` (id, name, type: preset|custom, tokens_json, template_name, version, is_deleted)

### 关键决策
- **内容一文一站**（不跨站）。避免 N:N 复杂性
- **栏目树** = 邻接表 + 物化路径双写（`path` 字段 `/1/3/7/` 便于子树查询）
- **软删除**：所有业务表加 `is_deleted BOOLEAN DEFAULT FALSE` + `deleted_at`
- **版本永不删**：`content_versions` 表无 `is_deleted`
- **主题版本**：`themes.version` 每次更新 +1，用于回滚
- **媒体去重**：`media.md5 UNIQUE`，上传时先查

## 6. API 设计

**遵循**：`docs/02-API-规范.md`（P0 已写）

### P1 新增端点（清单）
- `GET/POST /api/v1/sites`
- `GET/PATCH/DELETE /api/v1/sites/{id}`
- `GET/POST /api/v1/sites/{id}/members`
- `DELETE /api/v1/sites/{id}/members/{user_id}`
- `GET/POST /api/v1/taxonomies`
- `GET/PATCH/DELETE /api/v1/taxonomies/{id}`
- `GET/POST /api/v1/contents`（含分页 + 过滤 + 搜索）
- `GET/PATCH/DELETE /api/v1/contents/{id}`
- `POST /api/v1/contents/{id}/versions`（保存新版本）
- `GET /api/v1/contents/{id}/versions`（版本列表）
- `POST /api/v1/contents/{id}/publish`
- `GET /api/v1/media`（分页）
- `POST /api/v1/media/presigned-upload`（生成 MinIO 上传 URL）
- `POST /api/v1/media/confirm`（上传完成回调）
- `DELETE /api/v1/media/{id}`

### 关键约束
- **所有列表 API 必须分页**：`?page=1&page_size=20`（默认 20，最大 100）
- **过滤用 query**：`?status=draft&site_id=xxx`
- **响应统一格式**：`{ data: T[], pagination: { total, page, page_size } }`
- **错误用 HTTP 状态码**（不要全部 200）

## P3.6.2 媒体库增强 (E+F+G+H)

### E. 缩略图生成
- migration 0024: media 加 thumb_small_key / thumb_large_key / thumb_status (pending/done/failed)
- worker `app.workers.media.generate_thumbnails` 用 Pillow 生成 webp 200/800
- **重要坑**: celery worker 有自己的 event loop, `asyncio.run` 创新 loop 里 `asyncpg` 会报 "attached to a different loop". 必须用 `new_event_loop + dispose engine` 模式 (跟 run_publish 一样). 抄 publish.py 跑法.
- 上传触发: `direct_upload` + `presign+confirm` 两个入口都加 `_trigger_thumb_task(m.id)` 异步调用
- API 返回: list/get 都加 `thumb_small_url` + `thumb_large_url` + `thumb_status`
- 镜像 rebuild: pyproject 加 Pillow 不会自动生效, `docker compose build worker api` 后 `up -d`

### F. 媒体标签系统 (替代文件夹扁平化)
- migration 0025: media_tags (site_id, name, color) + media_tag_links (N:N)
- `UniqueConstraint("site_id", "name")` 标签站级唯一
- migration 写 `server_default` 必须用 `sa.text("gen_random_uuid()")`, 字符串字面量会报 invalid input syntax

### G. 全局素材库 (跨站共享)
- migration 0026: media.is_shared BOOL (partial index where=true)
- 列表查询默认 WHERE site_id=X OR is_shared=true, 共享池自动跨站可见
- `?only_shared=true` 只看共享池
- share/unshare 端点需 super_admin
- 后端 dict 返字段时容易漏 (is_shared 漏了一次才补), 抽个 _to_list_item helper 没用上, 直接每个 endpoint 重复构造是历史包袱

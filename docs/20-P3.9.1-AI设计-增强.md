# 20. P3.9.1 — AI 设计 tab 增强 (hunk-level accept + live preview)

> **v1.0 · 2026-06-11 · holy 反馈 #10867**

> 1. **Hunk-level accept** — 不再全接受/全拒, 按 diff hunk 选
> 2. **Live preview iframe** — 接受前先看真渲染, 不再赌
>
> 文档依据: P3.9 §4 决策, holy 反馈 "Diff 视图无法逐段接受" + "改后没看到真渲染"

## 1. 背景 (P3.9 痛点)

P3.9 (2026-06-10 23:00) 实现了 4 个 AI 动作 (optimize_design / responsive / a11y / seo),
LLM 改完模板后弹 `HtmlDiffView` 文本对比. 但有两个致命痛点:

| 痛点 | 影响 | 频率 |
|------|------|------|
| 只能"全接受 / 全拒" | LLM 改 30 行, 你只想留 5 行 → 全拒重做 或 全接受后手动回滚 | 100% AI 任务 |
| 改完没真渲染预览 | 接受后才知道 CSS 错位 / HY_ escape / 布局塌陷 → build 后才发现 | 50% AI 任务 |

**P3.9.1 解决这俩**, 接受 = 跟 GitHub PR 一样, 逐 hunk 选; 预览 = 弹 diff 旁边开 iframe, 边看边选.

## 2. 决策 (Q1-Q4)

### Q1: Hunk 怎么切分? (A=B 按 GitHub unified diff)
- **A**: 按 changed 段, 中间夹 ≤3 行 unchanged 算上下文, 合并成 1 hunk
- B: 任何 changed 段独立 (hunk 太多碎)
- C: 不切, 整段当 1 hunk (回到 P3.9)

**决策 A** (跟 GitHub / GitLab 一致, 业内通用)

### Q2: Hunk 边界上下文多少行? (A=3)
- A: 3 行 (GitHub 默认)
- B: 5 行
- C: 0 行 (不显示上下文)

**决策 A**

### Q3: Live preview 怎么渲染? (A=iframe srcDoc)
- A: `<iframe srcDoc={renderedHtml}>` (隔离 sandbox, 不污染主页)
- B: 直接 `dangerouslySetInnerHTML` 到主区 (破坏 iframe 隔离)
- C: 弹模态 (遮挡 diff, 不便对比)

**决策 A** + `sandbox="allow-same-origin"` (允许本站 cookie 跟 fetch)

### Q4: Preview 触发频率? (A=500ms debounce)
- A: 500ms debounce (勾选 checkbox 0.5s 后才打 API)
- B: 实时 (每个勾选都打)
- C: 手动"刷新预览"按钮

**决策 A** (B 太频繁打爆后端, C 不够自然)

## 3. 实现

### 3.1 Hunk 切分算法 (P3.9.1 D1)

`frontend/src/components/HtmlDiffView.tsx` 新增 `buildHunks(diffParts)`:

```ts
type Hunk = {
  id: number;
  indices: number[];              // 引用到原 diffParts 下标
  oldLines: { text, kind: 'unchanged'|'removed'|'skip' }[];
  newLines: { text, kind: 'unchanged'|'added'|'skip' }[];
  changes: number;                // 净改动行数
  mergeOnAccept: string;          // 接受 = 上下文 + added
  mergeOnReject: string;          // 拒绝 = 上下文 (保留 removed)
};
```

**算法** (`buildHunks` line 81-152):
1. 扫描 `diffParts`, 找下一段 changed (added/removed)
2. 起点 = `i - CONTEXT_LINES` (向前 3 行 unchanged)
3. 终点: 串起连续 changed + 中间 ≤3 行 unchanged; 大块 unchanged 断开
4. 终点 + 3 行 unchanged 收尾
5. 一个 hunk = `[start, endWithCtx)` 范围
6. 算 `mergeOnAccept` = unchanged + added, `mergeOnReject` = unchanged + removed 保留

**单测** (用 node 跑 `diffLines` 验证):
- 输入: `'a\nb\nc\nd\ne\nf\n'` → `'a\nB\nc\nd\nE\nf\n'`
- 输出: 1 hunk (`b` 改 `B` + `e` 改 `E`, 中间 `c/d` 是 2 行 ≤3 上下文, 合并)
- changes: 4 行 (2 add + 2 remove)

### 3.2 Hunk-level Accept (P3.9.1 D2)

`HtmlDiffView` 状态:
```ts
const [acceptedHunks, setAcceptedHunks] = useState<Set<number>>(
  () => new Set(hunks.map(h => h.id)),  // 默认全接受 (P3.9 旧行为)
);
```

合成 `mergedHtml` (line 175-200):
```ts
const mergedHtml = useMemo(() => {
  const partHunkId = new Map<number, number>();
  hunks.forEach(h => h.indices.forEach(idx => partHunkId.set(idx, h.id)));
  const out: string[] = [];
  for (let k = 0; k < diffParts.length; k++) {
    const part = diffParts[k];
    const hunkId = partHunkId.get(k);
    const isAccepted = hunkId === undefined ? true : acceptedHunks.has(hunkId);
    if (isAccepted) {
      if (part.removed) continue;  // 接受: 跳过 removed
      out.push(part.value);
    } else {
      if (part.added) continue;     // 拒绝: 跳过 added
      out.push(part.value);
    }
  }
  return out.join('');
}, [diffParts, hunks, acceptedHunks]);
```

UI 操作 (line 285-300):
- 每个 hunk 顶 header = checkbox + `#N/总数 ±改动行数`
- 取消勾选 = 拒绝该 hunk (用旧版)
- "全接" / "全拒" 一键切
- "应用选中" 按钮带 mergedHtml 字符数显示
- 顶栏实时显示 `+已接受 / −已拒绝` 统计

### 3.3 Live Preview (P3.9.1 D3)

`HtmlDiffView` 嵌入 `<LivePreview layoutId html={mergedHtml} />` 子组件:

```tsx
function LivePreview({ layoutId, html }) {
  const [debouncedHtml, setDebouncedHtml] = useState(html);
  useEffect(() => {                       // 500ms debounce
    const t = setTimeout(() => setDebouncedHtml(html), 500);
    return () => clearTimeout(t);
  }, [html]);
  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    layoutsApi.preview(layoutId, debouncedHtml)  // POST /layouts/{id}/preview
      .then(r => { if (!cancelled) setPreviewHtml(r.html); })
      .catch(e => { /* 错误显示 */ });
    return () => { cancelled = true; };
  }, [layoutId, debouncedHtml]);
  return (
    <div>
      {warnings/errors && <警告条>}
      <iframe srcDoc={previewHtml} sandbox="allow-same-origin" />
    </div>
  );
}
```

**后端复用** (P3.6 D2-D5 已实现): `POST /layouts/{id}/preview` 走 `layout_renderer.render`, 返回 `html / warnings / errors`. 传 `body.html` 用临时 HTML 渲染, 不入库.

**Toggle 按钮**: "实时预览" 按钮默认显示 (有 layoutId 就显示), 可隐藏给宽屏用户.

## 7. 踩坑 (本次 + 历史)

### 7.1 React 19 ref 类型 (`useRef<HTMLPreElement | null>` 不接受)

**症状**: `RefObject<HTMLPreElement | null>` 不能赋给 `<pre ref={...}>` (TypeScript error TS2322)
**修**: 改用 `React.MutableRefObject<HTMLPreElement | null>` (跟原 HtmlDiffView 写法一致)

### 7.2 P3.7.2+ vite proxy bug 顺手修

**症状**: `server.proxy = {'/api/': { target: 'http://api:8000' }}` 配了但 `/api/v1/sites` 返 SPA index.html, queryFn 拿 undefined
**根因**: vite 5 SPA fallback (`htmlFallback`) 优先级高于 user proxy, 5.4.21 已知 quirk
**修**: 在 `disableHmrPlugin.configureServer` 加手写 middleware 拦截 `/api/` → 走 `http.request(api:8000)`
**预防 (P3.9.1+#108)**:
- **永远** 改完 vite.config.ts 后 `curl http://localhost:18889/api/v1/xxx` 验证, 不只看 build 通过
- **永远** admin 容器重启后 `rm -rf node_modules/.vite/deps` 清 cache
- **永远** VITE_API_BASE 在 dev 设成 `http://localhost:80/api/v1` (走 host nginx) 避免 vite proxy 坑

### 7.3 minimax provider 多 default 撞车

**症状**: `ai_providers` 表有 5 条 minimax provider, 3 条 `is_default=true`, 系统随机选, 选到 `https://api.minimaxi.com/anthropic/v1` 的坏 provider → 404
**根因**: P3.9 时期 add provider 没 enforce `is_default` 唯一约束
**修**: 临时 `update ai_providers set is_default=false where id=...; update ai_providers set is_default=true where id=...;` (选 f5c2c849 那个)
**预防 (P3.9.1+#109)**:
- **永远** `ai_providers` 表应当加 `partial unique index` 约束 `(is_default=true)` 最多 1 条
- **永远** 改 backend 后 worker 要 `docker compose restart worker` (P3.8.9 教训 #16)
- **永远** 跑 AI 任务前看 `SELECT provider, model, base_url FROM ai_providers WHERE is_default=true` 确认

## 10. 子模板速查面板 (PartialsPanel, 2026-06-11)

**背景**: holy 反馈 #11133 问"子模板如何被其他模板引用", 选 A — 在模板编辑页加"该站所有 partial code"速查列表.

### 10.1 子模板引用机制 (回顾)

后端早就有 2 种引用方式:

1. **`<HY_TEMPLATE _code="xxx" />`** — 按 code 引用 (推荐, 站内复用)
   - 模板写: `<HY_TEMPLATE _code="header-v1" />`
   - 走 `factory.templates_by_code` dict (`backend/app/services/page_renderer.py:456-460` build_site 预加载**所有** site layouts)
   - 同一站任意 scope 的 layout 都能引用
   - 防重名: 后加载覆盖前加载 (scope=partial 优先 page)

2. **`<HY_INCLUDE _file="x.html" />`** — 按文件名引用 (历史 / 外部文件)
   - 模板写: `<HY_INCLUDE _file="snippet.html" />`
   - 走 `ctx.partials` dict 优先, 否则查 `ctx.partials_dir / x.html` 文件系统
   - 防路径穿越 (`..` / 绝对路径被拦), 递归深度限制
   - 多用于复用**静态 HTML 片段** (写死在文件里, 不进 layouts 表)

### 10.2 修法

新组件 `frontend/src/components/PartialsPanel.tsx` (5473 字节):
- 拉 `layoutsApi.list(siteId, { scope: 'partial' })` 列本子模板 (缓存 5 min)
- Card + 折叠列表, 行内显示 name / code / version
- 点击行 → `navigator.clipboard.writeText('<HY_TEMPLATE _code="x" />')` 复制整段 + toast
- 兜底: clipboard 不可用时 `window.prompt` 手动复制
- 0 子模板: 提示"在「模板管理」新建一个"

### 10.3 接入

`frontend/src/pages/LayoutEditPage.tsx` 在 `LayoutReferencesCard` 之后插 `<PartialsPanel siteId compact />`:
- LayoutReferencesCard = **反向**: "哪些栏目/文章用了此模板" (P3.7.4)
- PartialsPanel = **正向**: "本站可引用的子模板" (P3.9.1+)

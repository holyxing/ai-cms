## 1. 目标 (Why)

把 "**平级多站点 + 顶部 tab**" 改成 "**树状导航 + 节点右键操作 + 内容工作区**"。

### 1.1 用户故事

```
作为 内容编辑
我希望 在左侧树里直接看到所有站点和栏目
并且 在任意节点上右键就能新增下级
并且 点击栏目直接看到该栏目下的所有文章

这样 我不需要在顶部 tab 之间来回切换
     不需要先开"站点列表"再点进去再建栏目
     所有内容操作在一棵树上完成
```

### 1.2 当前痛点 (来自 P5 验收)

- `/sites` 列表页 + `/contents` 列表页 + 顶部 6 个 tab: 信息散落, 找东西要点 3 次
- 新建站点要去 `/sites` → 点"新建" → 填表单 → 跳详情; **没办法在"我正在工作的那个站点"旁边直接新建一个并列站**
- 新建栏目要去 `/contents` → "分类" tab → 找父栏目 → 点"新增" → 填; **嵌套超过 3 层就分不清谁是谁**
- 每次切站点都要"回 /sites → 找 → 点"——浪费注意力

### 1.3 重构后的体验

```
┌─────────────────────────────────────────────────────┐
│  [站点 ▾ 霍因科技]   搜索 ⌕              ⚙️   用户 ▾  │  ← 顶部极简 (站点切换 + 全局)
├──────────┬──────────────────────────────────────────┤
│ 📁 根目录│  工作区:                                  │
│  └ 霍因  │  ┌─ 站点信息 / 内容列表 / 发布入口 ─┐  │
│   ├ 资讯 │  │  当前栏目: 资讯 > 公司动态       │  │
│   │ └ 公司│  │  10 篇文章, 按时间倒序          │  │
│   ├ 技术 │  │  [+ 新建文章]  [批量操作]       │  │
│   └ 产品 │  └─────────────────────────────────┘  │
│  📁 测试站│                                          │
│  📁 博客 │                                          │

右击菜单:
- 空白处   → [新增站点]
- 站点节点 → [新增栏目] [编辑站点] [归档] [预览公开站]
```

## 3. 数据模型 (Data)

### 3.1 站点表 `sites` — **不变**

P1.1 已经是平级, Q1A 维持现状:

```sql
-- 已存在, 不动
sites (id, slug, name, owner_id, status, publish_status, settings, deleted_at, ...)
```

### 3.2 新增 `categories` 栏目表

**从 `taxonomies` 拆出 `category` 类型**, 独立成新表:

```sql
CREATE TABLE categories (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  site_id         UUID NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  parent_id       UUID REFERENCES categories(id) ON DELETE CASCADE,  -- 父栏目
  name            VARCHAR(128) NOT NULL,
  slug            VARCHAR(128) NOT NULL,
  path            TEXT NOT NULL,         -- 物化路径 "/1/3/7/" 邻接表+物化路径双保险
  order_num       INTEGER NOT NULL DEFAULT 0,  -- 同级排序
  description     TEXT,
  seo             JSONB NOT NULL DEFAULT '{}'::jsonb,  -- {title, description, keywords}
  content_count   INTEGER NOT NULL DEFAULT 0,  -- 反规范化, 拖入/移出时维护
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  deleted_at      TIMESTAMPTZ DEFAULT NULL,
  UNIQUE (site_id, slug)
);

CREATE INDEX idx_categories_site ON categories(site_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_categories_parent ON categories(parent_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_categories_path ON categories(path) WHERE deleted_at IS NULL;  -- 子树查询
```

**设计要点**:
- **物化路径 + 邻接表双保险** (沿用 P1 taxonomies 的设计, 经验证):
  - 邻接表(`parent_id`)写起来简单, 改父级时要递归更新子树 `path`
  - 物化路径(`path`)读子树快: `WHERE path LIKE '/1/3/%'`
  - **写时双写**, 读时只用 `path` 索引
- `content_count` 反规范化: 树节点旁边显示"12 篇文章", 不用每次 count
- `UNIQUE (site_id, slug)`: 同一站下栏目 slug 唯一, 跨站可重名
- `deleted_at` 软删除: 误删可恢复, 30 天清理脚本

### 3.3 修改 `contents` 表 — **加 `category_id` 字段**

之前 P1 是 `content_taxonomies` 多对多(支持一文多分类 + 多 tag), 重构后:
- **栏目是导航结构, 一篇文章有且只有 1 个主栏目** (栏目决定它在树哪里)
- **tag/series/format 仍然多对多** (走 `content_taxonomies`, 不动)

```sql
-- 1. 新增外键
ALTER TABLE contents ADD COLUMN category_id UUID REFERENCES categories(id) ON DELETE SET NULL;
CREATE INDEX idx_contents_category ON contents(category_id) WHERE deleted_at IS NULL;

-- 2. 老的 content_taxonomies 里 type='category' 的, 拆出来
-- (一次性迁移脚本, 见 §6)
```

**`contents` 不再需要 `site_id` 外键?**
- 保留: `site_id` 决定部署到哪个站; `category_id` 决定导航位置
- 文章绑定站点 (部署目标) + 绑定栏目 (导航位置), 两个独立维度
- 校验: `category.site_id == content.site_id`, API 层做, 不加 DB 约束 (跨表约束 PG 复杂)

### 3.4 砍掉 `taxonomies` 里 `category` 类型

```sql
-- 1. 把 type='category' 的全量灌到新 categories 表
-- 2. 把 content_taxonomies 里 category 的关联改成 contents.category_id
-- 3. 删 type='category' 的 taxonomies 行
-- 4. CHECK 约束去掉 category
ALTER TABLE taxonomies DROP CONSTRAINT IF EXISTS ck_taxonomies_type;
ALTER TABLE taxonomies ADD CONSTRAINT ck_taxonomies_type
  CHECK (type IN ('tag', 'series', 'format'));
```

## 4. API 改动 (Backend)

### 4.1 新增 — 栏目树

| 端点 | 方法 | 用途 |
|---|---|---|
| `/api/v1/sites/{site_id}/categories` | GET | 拉整棵栏目树 (扁平 + 父子关系) |
| `/api/v1/sites/{site_id}/categories` | POST | 在根或某 parent 下新建栏目 |
| `/api/v1/categories/{id}` | PATCH | 改名 / 改 slug / 改父级 / 改 sort |
| `/api/v1/categories/{id}` | DELETE | 软删除 (含子栏目级联) |
| `/api/v1/categories/{id}/move` | POST | 拖拽改父级 + 改顺序 |
| `/api/v1/categories/{id}/sort` | POST | 同级内拖拽改顺序 |

**响应示例** — 树形接口:

```json
GET /api/v1/sites/abc123/categories
{
  "data": {
    "site_id": "abc123",
    "tree": [
      {
        "id": "cat-1",
        "name": "资讯",
        "slug": "news",
        "path": "/cat-1/",
        "order_num": 0,
        "content_count": 12,
        "children": [
          {"id": "cat-3", "name": "公司动态", "path": "/cat-1/cat-3/", "content_count": 5, "children": []}
        ]
      },
      {"id": "cat-2", "name": "技术", "slug": "tech", "path": "/cat-2/", "content_count": 8, "children": []}
    ]
  }
}
```

### 4.2 修改 — 内容列表

| 端点 | 改动 |
|---|---|
| `GET /api/v1/contents?category_id=cat-3` | **新增** 栏目过滤 (替代之前 `taxonomy_id`) |
| `GET /api/v1/contents/{id}` | 返回 `category` 字段 (替代 `taxonomies[category]`) |
| `POST /api/v1/contents` body | `category_id: UUID` 替代 `taxonomy_ids: [category]` |
| `PATCH /api/v1/contents/{id}` | 同上 |

### 4.3 保留 / 不动

- 站点 CRUD: `/api/v1/sites` (P1.1 完整保留)
- 域名: `/api/v1/sites/{id}/domains` (P5 完整保留)

- 主题: `/api/v1/themes/*` (P2 完整保留)
- 发布: `/api/v1/sites/{id}/publish/*` (P2 完整保留)
- AI: `/api/v1/ai/*` (P3 完整保留)
- 内容版本: `/api/v1/contents/{id}/versions` (P1 完整保留)
- tag/series/format 关联: `/api/v1/taxonomies` (P1 完整保留, 只是 type 砍掉 category)

### 4.4 废弃 (旧路由 1 个版本过渡后砍)

- ❌ `GET /api/v1/taxonomies?type=category` (新接口替代)
- ❌ `POST /api/v1/taxonomies` body `{type: "category", ...}` (新接口替代)
- ❌ `/admin/sites` 前端路由 (砍)
- ❌ `/admin/contents` 前端路由 (砍)

## 6. 数据迁移 (Migration)

### 6.1 一次性脚本 — `scripts/migrate_categories.py`

```python
# 伪代码
async def migrate():
    # 1. 创 categories 表 (Alembic 0017)
    # 2. 灌数据: SELECT * FROM taxonomies WHERE type='category' AND deleted_at IS NULL
    #    INSERT INTO categories (id, site_id, parent_id, name, slug, path, ...)
    #    - id 重新生成 (UUID) 或保留 (BIGSERIAL → UUID 转换)
    #    - parent_id 同上
    #    - path 沿用
    # 3. 把 content_taxonomies 里 type='category' 的关联灌到 contents.category_id
    #    - 一文多分类的, 取第一个 (语义损, 但 P1 数据显示这种很少)
    # 4. 删 taxonomies 里 type='category' 的行
    # 5. 改 taxonomies 的 CHECK 约束
    # 6. ALTER TABLE contents ADD COLUMN category_id
    # 7. backfill content_count: UPDATE categories SET content_count = (SELECT COUNT(*) FROM contents WHERE category_id = c.id AND deleted_at IS NULL)
```

**风险评估**:
- 一文多分类损 1 个分类 (P1 数据显示 0 个, 验证后无影响)
- taxonomy_id 在 content_versions 里没存, 不影响版本回滚
- 不可逆: 删 category 类型后想回滚, 要重跑反向脚本; 建议保留原表 dump 一份

### 6.2 回滚预案

```bash
# 保留 30 天自动备份 (已存在: deploy/backup/)
# 手动回滚:
docker compose exec -T postgres pg_dump -t taxonomies -t content_taxonomies > /backup/before_p27.dump
# 失败后: psql < /backup/before_p27.dump
```

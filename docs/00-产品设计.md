# AI-CMS 产品设计文档

> 一个由 AI 深度协作的多站点内容管理与静态发布平台
>
> **版本**：v0.1（设计稿，待评审）
> **技术栈**：FastAPI + React + Astro + PostgreSQL + Docker
> **最后更新**：2026-06-04

---

## 1. 一句话定位

> **让不懂设计/HTML 的人也能在几分钟内建好一个内容站点；让懂设计的人能用 AI 加速 10 倍。**

---

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| **超管**（平台 owner） | 开通站点、管理全局用户、配 AI 模型 |
| **站点管理员** | 管一个站点的所有内容、主题、成员、域名 |
| **编辑** | 写文章、调整版块、配图 |
| **作者** | 只能写自己的草稿，提交审核 |
| **访客**（公开） | 访问静态发布的公开站点 |

**典型用户故事**：
- "我开了家小公司，想 10 分钟搞个官网" → AI 选主题 → 填公司信息 → 发布
- "我是运营，每天要发公众号推文" → 打开后台 → 富文本写文章 → AI 配图/改稿 → 一键发布
- "我负责 5 个品牌站" → 切站点 → 改样式 token → 一键重新发布

| 模块 | MVP（第 1 阶段） | 完整版 |

**流量分两条**：
- **后台流量**：`/admin/*` → React SPA → 调 FastAPI
- **公开流量**：`/sites/<slug>/*` → Nginx 直接吐静态 HTML（不经过 API）

**AI 流量**：用户在 Admin 里和 AI 交互 → FastAPI → AI 抽象层 → 选 OpenAI/Anthropic/Ollama

## 5. 数据模型（PostgreSQL）

### 5.1 核心表（按依赖顺序）

```sql
-- ========= 平台层 =========

users              -- 用户（跨站点）
id, email, password_hash, name, avatar, is_active, created_at

roles              -- 角色
id, code (super_admin/site_admin/editor/author), name, description

sites              -- 站点
id, slug, name, domain, description, owner_id, status, created_at

site_members       -- 站点-用户-角色（多对多 + 角色）
id, site_id, user_id, role_id, created_at

ai_providers       -- AI 服务商配置
id, code (openai/anthropic/ollama), name, api_base, api_key_enc, default_model

themes             -- 主题库
id, code, name, description, preview_url, theme_json (JSONB), is_builtin

-- ========= 站点层 =========

site_settings      -- 站点级配置（KV）
id, site_id, key, value (JSONB), updated_at

current_theme      -- 站点当前主题快照（themes.theme_json 的拷贝 + 站点专属改写）
id, site_id, theme_id, tokens (JSONB), components (JSONB), updated_at

taxonomies         -- 分类法（栏目/标签）
id, site_id, type (category/tag), slug, name, parent_id, sort, description

contents           -- 内容（文章/页面）
id, site_id, type (article/page), slug, title, summary,
   blocks (JSONB),         -- Tiptap JSON
   cover_media_id,
   author_id, status (draft/pending/published), published_at,
   seo (JSONB),            -- title/description/og
   created_at, updated_at

content_revisions  -- 内容版本
id, content_id, version, blocks (JSONB), author_id, created_at, change_note

content_taxonomies -- 内容-分类 多对多
content_id, taxonomy_id

menus              -- 菜单
id, site_id, name, location (header/footer/sidebar), items (JSONB)

media              -- 媒体库
id, site_id, filename, mime, size, width, height, alt,
   storage_key,        -- MinIO object key
   uploaded_by, created_at

-- ========= AI 层 =========

ai_jobs            -- AI 任务记录
id, site_id, content_id (可空), provider, model, task_type (write/translate/design/audit/...),
   prompt, response, tokens_in, tokens_out, status, created_at, finished_at

ai_suggestions     -- AI 草稿/建议（待用户采纳）
id, ai_job_id, target (blocks/theme/taxonomy), payload (JSONB), status (pending/applied/rejected)

-- ========= 发布层 =========

publish_jobs       -- 发布任务
id, site_id, trigger (manual/scheduled/webhook), status, started_at, finished_at,
   artifact_path, log

publish_history    -- 发布产物快照
id, site_id, version, artifact_url, file_count, size_bytes, created_at

-- ========= 审计 =========

audit_logs
id, site_id, user_id, action, target_type, target_id, meta (JSONB), created_at
```

### 5.2 JSONB 的设计哲学

| 字段 | 为什么用 JSONB |
|---|---|
| `contents.blocks` | Tiptap JSON 本身是树形，关系表拆不开 |
| `current_theme.tokens` | design tokens 是任意 key-value 嵌套 |
| `current_theme.components` | 主题里组件参数也是结构化数据 |
| `menus.items` | 菜单是任意嵌套的树 |
| `contents.seo` | 灵活 + 易于扩展 |
| `ai_suggestions.payload` | AI 输出格式不可预测 |

**索引策略**：
- `blocks` 上建 GIN 索引（支持全文检索"包含某关键词的文档"）
- `tokens` 上建表达式索引（按主色筛选主题）
- 其他 JSONB 暂时只走全表扫描，量大了再说

## 6. AI 抽象层设计

### 6.1 核心原则

**AI 是"协作创作者"，不是"装饰"**。每个写/改/配/检的动作，背后都有 AI 在场。

### 6.2 抽象接口

```python
# backend/app/agents/base.py
class AIProvider(Protocol):
    name: str
    async def chat(self, messages: list[Message], **opts) -> AIResponse: ...
    async def stream_chat(self, messages: list[Message], **opts) -> AsyncIterator[str]: ...
    async def embed(self, texts: list[str]) -> list[list[float]]: ...

class AIRouter:
    """根据任务类型选最合适的 provider + model"""
    def route(self, task: AITask) -> AIProvider: ...
```

### 6.3 任务类型与默认路由

| 任务 | 推荐 provider | 默认 model | 说明 |
|---|---|---|---|
| `write_article` | openai/anthropic/ollama | gpt-4o / claude-sonnet / qwen2.5 | 写长文 |
| `rewrite_tone` | openai/anthropic/ollama | gpt-4o-mini / claude-haiku | 改语气 |
| `translate_zh` | openai/anthropic/ollama | gpt-4o-mini | 中英互译 |
| `design_suggest` | openai/anthropic | gpt-4o / claude-sonnet | 给 design token 改建议 |
| `audit_content` | openai/anthropic/ollama | gpt-4o-mini / qwen2.5 | SEO/可访问性/死链 |
| `generate_layout` | openai/anthropic | claude-sonnet | 根据描述生成首页布局 |
| `embed_content` | ollama / openai | bge-m3 / text-embedding-3 | 向量化 |

**可降级**：如果默认 provider 不可用，自动 fallback 到下一个。

### 6.4 AI 在编辑流程里的"嵌入点"

```
┌─ 新建文章 ─────────────────────────────────────────┐
│  [空白] [AI 起稿] [从模板]                         │
│      ↓                                           │
│  AI 起稿：输入主题 → 选择语气/长度/受众 → 生成    │
│      ↓                                           │
│  Tiptap 编辑器（带 AI 侧栏）                       │
│      ↓                                           │
│  AI 侧栏能力：                                     │
│   • 选中段落 → 改语气/翻译/续写/精简              │
│   • 全文 → SEO 审计/可读性打分/敏感词             │
│   • 一键 → 配图（生成 alt）                       │
└────────────────────────────────────────────────────┘

┌─ 调样式 ───────────────────────────────────────────┐
│  当前主题 → Token 面板（颜色/字体/间距/圆角）     │
│      ↓                                           │
│  [AI 调样式] 对话框：                              │
│   "更年轻一点，主色偏蓝"                           │
│   "做暗色模式"                                    │
│   "参考 Notion 的简洁感"                          │
│      ↓                                           │
│  AI 返回 token 改写方案 → 实时预览 → 一键应用      │
└────────────────────────────────────────────────────┘

┌─ 检查 ─────────────────────────────────────────────┐
│  站点健康检查 Agent：                              │
│   • SEO 审计（每篇文章的标题/meta/结构化数据）     │
│   • 死链扫描                                      │
│   • 图片 alt 覆盖率                               │
│   • 内容质量（重复/过短/标题党）                   │
│   • 可访问性（对比度/标题层级/alt）               │
│   • 给出修复建议（可一键应用）                     │
└────────────────────────────────────────────────────┘
```

## 7. 主题系统（Design Tokens + 组件）

### 7.1 两层结构

```
Theme
├── Tokens（设计变量）—— AI 改的就是这层
│   ├── color: { primary, secondary, bg, text, ... }
│   ├── typography: { fontFamily, fontSize, lineHeight, ... }
│   ├── spacing: { xs, sm, md, lg, xl, ... }
│   ├── radius: { sm, md, lg, full }
│   ├── shadow: { sm, md, lg }
│   └── breakpoint: { sm, md, lg, xl }
│
└── Components（组件变体映射）—— 暂不开放 AI 改
    ├── button: { primary, secondary, ghost }
    ├── card: { default, feature }
    └── section: { default, hero, cta }
```

### 7.2 内置主题（MVP）

- `default` —— 通用博客
- `business` —— 企业官网
- `tech` —— 极客风（暗色优先）
- `magazine` —— 杂志型（大图卡）
- `minimal` —— 极简风

每个主题一份 `theme.json`，就是一组 token + 组件默认参数。

### 7.3 静态站点导入（高级功能）

```
用户输入 URL 或上传 HTML+CSS+JS zip
      ↓
解析器（Playwright + PostCSS）:
  1. 抓取所有 HTML/CSS
  2. 提取颜色 → 生成 token.color
  3. 提取字体 → 生成 token.typography
  4. 提取间距/圆角 → 生成 token.spacing/radius
  5. 提取布局 → 生成 block schema
      ↓
生成预览主题 → 用户可编辑 → 存入 themes
```

**MVP 阶段不做，先做手动导入 JSON theme.json。**

## 8. 静态发布流水线

```
内容就绪
  ↓
点击"发布" / 定时任务 / Webhook
  ↓
Celery 任务触发
  ↓
SSG 构建（Astro）
  ├── 拉取站点内容（通过内部 API）
  ├── 按主题渲染所有路由
  ├── 输出到 /sites/<slug>/dist/
  └── 记录到 publish_history
  ↓
分发
  ├── 默认：保留在容器内，Nginx 吐文件
  ├── 可选：rsync 到挂载目录
  └── 可选：推 S3/OSS
  ↓
发布完成 → 通知用户
```

**关键设计：**
- SSG 跑在容器内（Node 22 镜像）
- Astro 通过 `Astro.fetch()` 或内部 HTTP 调 FastAPI 拉数据（构建时）
- 构建产物打 tag 进 `publish_history`，可回滚

## 10. Docker 部署（单机）

```yaml
# deploy/docker-compose.yml（核心服务）
services:
  api:        # FastAPI :8000
  worker:     # Celery worker
  beat:       # Celery beat（定时）
  admin:      # React :5173 (dev) / nginx (prod)
  ssg:        # Astro 构建器（按需起）
  postgres:   # PG :5432
  redis:      # Redis :6379
  minio:      # MinIO :9000, :9001
  ollama:     # Ollama :11434 (可选, profile=ai-local)
  nginx:      # Nginx :80 (反代 + 静态托管)
```

**两个 profile**：
- 默认：不含 Ollama（轻量）
- `ai-local`：含 Ollama 跑本地模型

**首次启动**：
```bash
cp .env.example .env
docker compose up -d
docker compose exec api alembic upgrade head
docker compose exec api python scripts/seed.py   # 初始化超管 + 5 个主题
```

## 12. 验收标准（MVP 演示脚本）

> 1. 启动 → 登录超管
> 2. 新建站点"示例科技公司" → AI 选主题（选"business"）→ AI 调色（"主色改成科技蓝"）→ 生成首页
> 3. 新建栏目"产品介绍" / "新闻动态"
> 4. AI 起稿一篇新闻 → 编辑器微调 → AI SEO 审计 → 发布
> 5. 点击"发布站点" → 30 秒后访问 `http://localhost/sites/example`
> 6. 看到完整静态站点，UI 与编辑器内一致

**通过即视为 MVP 达成。**

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| AI 改样式失控 | **只让 AI 改 token，不让 AI 改 HTML/CSS 源码**；每次改动生成快照可回滚 |
| 静态生成慢 | MVP 内容少，无忧；后续做增量生成（只重生变化的页） |
| 多主题 Astro 模板维护成本 | 模板用一组参数化（Astro components + token），不做"每主题一套代码" |
| Tiptap 协作复杂 | MVP 不做实时协作，先单人编辑 |
| Ollama 镜像大 | 拆 profile，文档说"按需启用" |
| 中文 AI 质量 | 默认走 OpenAI/Anthropic，Ollama 备选；用户可手动指定 |

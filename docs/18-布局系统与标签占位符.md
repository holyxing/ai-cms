# 18 · 布局系统与标签占位符（HY_ Tags）

> **页面骨架层** —— 与 Block（内容元素层）解耦的模板系统。
> 站点布局、栏目布局、单页布局，都用同套机制：**HTML + HY_ 标签占位符**。

## 1. 设计理念（一句话）

> **HTML 管样式，标签管数据，发布时合体。**

- **布局文件** = HTML + 占位符（前端可视编辑，后端可解析）
- **HY_ 标签** = 编译时由后端/Astro 替换为真实数据
- **发布产物** = 纯静态 HTML，零运行时依赖
- **预览产物** = 同套 SSG 渲染，零差异

---

## 2. 三层布局模型

```
┌──────────────────────────────────────────────────────────┐
│  Layer 1：站点布局  (site_layout)                         │
│  → 整个站点共享的公共结构（Header / Footer / 全站侧栏）   │
│  → 1 套 HTML，可指定默认 + 多个变体（cover / minimal）   │
├──────────────────────────────────────────────────────────┤
│  Layer 2：栏目布局  (category_layout)                     │
│  → 栏目列表页的样式（列表 / 网格 / 时间线 / 卡片墙）     │
│  → 按栏目类型（article/page/gallery）自动匹配            │
├──────────────────────────────────────────────────────────┤
│  Layer 3：详情布局  (content_layout)                      │
│  → 单篇内容详情页的样式                                  │
│  → 头部/正文/侧栏/上下篇/评论位                          │
└──────────────────────────────────────────────────────────┘
```

**3 层独立编辑、独立预览、互不耦合。**

## 3. 标签命名规范

### 3.1 规则

| 规则 | 说明 |
|---|---|
| 前缀 | 全部 `HY_` 大写 + 下划线 |
| 写法 | `HY_xxx`（无值）或 `<HY_xxx _attr="yyy" />`（带属性） |
| 解析器 | 自实现（≈ 200 行 Python，**不引入 jinja2 / liquid**） |
| 大小写 | **不敏感**（`HY_SITE_NAME` = `hy_site_name`） |
| 注释 | `<!--HY_ comment -->` 原样保留（不渲染、不报错） |

### 3.1.1 HY_ 标签的属性命名（重要）

> **所有 HY_ 标签的业务属性必须 `_` 前缀**，与 HTML 原生属性**字面区分**。

```html
<!-- ✅ 正确：业务属性都加 _ 前缀 -->
<HY_CONTENTS _limit="10" _order="newest" _class="grid">...</HY_CONTENTS>
<HY_SITE_MENU _location="header" />
<HY_CAT_META _type="name" />
<HY_IF _condition="cat.has_children">...</HY_IF>
<HY_INCLUDE _file="site-header.html" />
<HY_ITEM_DATE _filter="date('Y-m-d')" />

<!-- ❌ 错误：业务属性无 _ 前缀，与 HTML 原生属性冲突 -->
<HY_CONTENTS limit="10" class="grid">...</HY_CONTENTS>
<HY_SITE_MENU location="header" />
```

**理由**：
- HTML 原生属性（`class` / `id` / `style` / `href` / `src`）可写在任何标签上
- 若 HY_ 标签允许 `class` / `id` 等，浏览器解析时**无法区分**是 HY_ 业务属性还是残留 HTML 属性
- 强制 `_` 前缀 → CodeMirror/解析器/编辑器 100% 能区分

**v0.1 黑名单**：禁止 HY_ 标签内出现**未加 `_` 前缀**的 `class` / `id` / `style` 属性，lint 报错。

### 3.2 两大类标签

#### A. 自闭合占位符（直接输出文本/HTML）

```html
<title>HY_SITE_NAME</title>
<img src="HY_SITE_LOGO" alt="HY_SITE_NAME" />
<a href="HY_SITE_URL">首页</a>
```

#### B. 容器型标签（包裹内容，控制循环/条件）

```html
<!-- 单值标签 (输出当前内容一次) -->
<HY_CAT_META _type="name" />

<!-- 循环标签 (输出 N 条内容) -->
<HY_CONTENTS _limit="10">
  <li>
    <a href="HY_ITEM_URL">HY_ITEM_TITLE</a>
    <time>HY_ITEM_DATE</time>
  </li>
</HY_CONTENTS>

<!-- 条件标签 (按条件包裹) -->
<HY_IF _condition="cat.has_children">
  <div class="sub-cats">子栏目：HY_CAT_CHILDREN</div>
</HY_IF>
```

## 4. 标签全集（v0.3，57 个 = 53 自闭合 + 4 容器）

> **三段式命名**：`HY_{层}_{字段}` 或 `HY_{层}_{动作}_{字段}`
> 例：`HY_SITE_NAME`（站点层+字段）/ `HY_CONTENTS_LIMIT`（内容层+动作+字段）

### 4.1 全局层（GLOBAL，4 个）

| 标签 | 输出 | 备注 |
|---|---|---|
| `HY_NOW` | 当前时间（构建时刻 UTC ISO） | 用于页脚"生成于…" |
| `HY_BUILD_ID` | 本次发布的 publish_history.id | 用于调试/审计 |
| `HY_THEME_VERSION` | 当前主题的 theme_versions.version | 主题溯源 |
| `HY_BASE_URL` | 站点根 URL（来自 site_domains.primary） | 自动加 https |

### 4.2 站点层（SITE，11 个）

| 标签 | 输出 | 类型 |
|---|---|---|
| `HY_SITE_NAME` | 站点名 | text |
| `HY_SITE_SLOGAN` | 站点副标题 | text |
| `HY_SITE_DESCRIPTION` | SEO description | text |
| `HY_SITE_KEYWORDS` | SEO keywords | text |
| `HY_SITE_LOGO` | logo URL（已是 CDN 绝对路径） | url |
| `HY_SITE_FAVICON` | favicon URL | url |
| `HY_SITE_URL` | 站点首页 URL | url |
| `HY_SITE_ICP` | ICP 备案号（来自 site.settings.icp） | text |
| `HY_SITE_COPYRIGHT` | 自动生成的 © 2024-2026 文本 | text |
| `HY_SITE_MENU _location="header"` | 导航菜单 HTML | html |
| `HY_SITE_MENU _location="footer"` | 页脚菜单 HTML | html |
| `HY_BREADCRUMB` | **统一面包屑**（按当前 context 自动：首页/栏目页/内容页/搜索页）| html |

### 4.3 栏目层（CATEGORY，9 个）—— 仅栏目页生效

| 标签 | 输出 | 类型 |
|---|---|---|
| `HY_CAT_ID` | 当前栏目 id | number |
| `HY_CAT_NAME` | 栏目名 | text |
| `HY_CAT_SLUG` | 栏目 slug | text |
| `HY_CAT_DESCRIPTION` | 栏目描述 | text |
| `HY_CAT_COVER` | 栏目封面图 URL | url |

| `HY_CAT_PARENT_NAME` | 父栏目名 | text |
| `HY_CAT_META _type="xxx"` | 任意栏目字段（name/slug/cover/...） | mixed |
| `HY_CATS _type="children"` | 循环子栏目容器（包裹内重复渲染） | container |

### 4.4 列表层（CONTENTS / ITEMS / CATS，5 个）—— 栏目页 + 任意带列表的页

| 标签 | 用法 | 输出 |
|---|---|---|
| `HY_CONTENTS _limit="10" _order="newest"` | **循环**容器，按栏目自动过滤 | 包裹的内容重复渲染 |
| `HY_CONTENTS_PAGINATION` | 分页 HTML（prev / 数字 / next） | html |
| `HY_CONTENTS_COUNT` | 当前列表总数 | number |
| `HY_CONTENTS_EMPTY` | **条件**：列表为空时显示包裹内容 | （无内容时输出包裹内容） |

| `HY_ITEM_URL` | 详情页 URL |
| `HY_ITEM_SUMMARY` | 摘要（无则取正文前 120 字） |
| `HY_ITEM_COVER` | 封面图 URL |
| `HY_ITEM_DATE` | 发布日期（YYYY-MM-DD） |
| `HY_ITEM_DATETIME` | 完整 ISO 时间 |
| `HY_ITEM_AUTHOR` | 作者名 |
| `HY_ITEM_CAT_NAME` | 所属栏目名 |
| `HY_ITEM_CAT_URL` | 所属栏目 URL |
| `HY_ITEM_TAGS` | 标签列表 HTML（自动生成链接） |
| `HY_ITEM_HITS` | 阅读量 |
| `HY_ITEM_META _type="xxx"` | 任意内容字段（title/slug/cover/...） |

### 4.5 详情层（CONTENT，5 个）—— 仅内容详情页生效

| 标签 | 输出 | 类型 |
|---|---|---|
| `HY_CONTENT_TITLE` | 标题 | text |
| `HY_CONTENT_BODY` | **Tiptap JSON → 已编译 HTML** | html |
| `HY_CONTENT_URL` | 当前页 URL | url |
| `HY_CONTENT_META _type="xxx"` | 任意字段（title/summary/cover/author/...） | mixed |
| `HY_CONTENT_PREV` | 上一篇 HTML（含链接） | html |
| `HY_CONTENT_NEXT` | 下一篇 HTML（含链接） | html |

### 4.6 控制流（CONTROL，3 个）—— 条件/循环/包含

| 标签 | 用法 | 行为 |
|---|---|---|
| `HY_IF _condition="..."` | 条件 | `cat.has_children` / `content.has_cover` 等 `xxx.has_xxx` 模式（v0.1） |
| `HY_FOR` | 循环 | v0.1 未实现，**别用**（容器内循环内置在 `HY_CONTENTS` / `HY_CATS`） |
| `HY_INCLUDE _file="xxx.html"` | 包含 | 引入公共片段（共用页头页脚） |

### 4.7 模板嵌套（HY_TEMPLATE，P3.7 新增）

| 标签 | 用法 | 行为 |
|---|---|---|
| `<HY_TEMPLATE code="header-v1" />` | 引入另一个 layout 模板 | 递归解析：取该 code 的 layout HTML，递归走原流程嵌入到当前位置。循环引用会报 422。 |

**业务示例** (`/sites/4e7134bd/...` 上):
- 创建 partial `code=header-v1`, `template_kind=partial`, HTML 包含 `<HY_SITE_MENU _location="header" />`
- 创建 partial `code=footer-corp`, HTML 包含 `<HY_SITE_ICP />` 等
- 在 home default 里:
  ```html
  <page>
    <HY_TEMPLATE code="header-v1" />
    <main><HY_SITE_HERO /><HY_CONTENTS>...</HY_CONTENTS></main>
    <HY_TEMPLATE code="footer-corp" />
  </page>
  ```
- publish 时 worker 递归解析, 产物含 header + main + footer 完整 HTML

**scope 与 template_kind**:
- `layouts.scope` 5 个值: `site` / `home` / `category` / `content` / `partial` (5 个固定目录)
- `layouts.template_kind` 2 个值: `page` (页面模板) / `partial` (子模板，可被嵌套)
- `HY_TEMPLATE` 可引用同站点任何 scope + template_kind=partial 的 layout

**预防点**:
- 循环引用 (A 包含 B，B 包含 A): worker 检测 `rendering_codes` set，发现环报 422
- 模板代码不存在: worker 报 422 + 提示可用模板列表

## 5. 占位符语法扩展

### 5.1 属性值（type 字段）

`HY_xxx_META _type="..."` 的 `type` 决定取什么字段：

```html
<!-- 等价 HY_CAT_NAME -->
<span>当前栏目：<HY_CAT_META _type="name" /></span>

<!-- 取 seo_title 字段（栏目 SEO 设置） -->
<title><HY_CAT_META _type="seo_title" /> | <HY_SITE_NAME /></title>
```

#### 5.1.1 META 标签 vs 专用标签的关系

> **META 是通用字段访问；专用标签是 META 的语法糖。**两者等价，**优先用专用标签**。

| 专用标签（推荐） | 等价 META |
|---|---|
| `HY_CAT_NAME` | `<HY_CAT_META _type="name" />` |
| `HY_CAT_COVER` | `<HY_CAT_META _type="cover" />` |
| `HY_CONTENT_TITLE` | `<HY_CONTENT_META _type="title" />` |
| `HY_ITEM_DATE` | `<HY_ITEM_META _type="published_at" />` |

**为什么优先用专用**：
- ✅ 语义化（编辑器自动补全、错误信息更友好）
- ✅ 自动加 filter（日期格式化、URL 绝对化）
- ✅ 性能略好（编译时直接绑定字段，无需查 schema）

**什么时候用 META**：
- 取不常用字段（如 `seo_title` / `hits` / `custom_field`）
- 循环内动态选字段（不常见，V2 再说）

**支持的 type**（取决于实体 schema）：
- 通用：`id` `name` `slug` `description` `cover` `url` `created_at` `updated_at`
- 栏目特有：`seo_title` `seo_description` `seo_keywords` `parent_id` `sort` `template`
- 内容特有：`title` `summary` `body` `cover` `author` `published_at` `hits` `tags`

### 5.2 过滤器（filter）

```html
<!-- 截取前 80 字 -->
<HY_CONTENT_BODY _filter="truncate(80)" />

<!-- 格式化日期 -->
<HY_ITEM_DATE _filter="date('Y-m-d')" />
<HY_ITEM_DATE _filter="date('Y年m月d日')" />

<!-- 默认值 -->
<HY_CAT_DESCRIPTION _filter="default('暂无描述')" />
```

**支持的 filter 集（v0.1，8 个）**：
| filter | 说明 | 适用 |
|---|---|---|
| `truncate(n)` | 截 N 字符 | text |
| `date(fmt)` | 格式化日期（PHP 风格） | date |
| `default(x)` | 空值替代 | any |
| `upper` `lower` | 大小写 | text |
| `strip_html` | 去 HTML 标签 | html |
| `urlencode` | URL 编码 | text |
| `abs_url` | 相对路径转绝对 | url |

### 5.3 注释与转义

```html
<!--HY_ 这是注释，发布时删除 -->
<HY_IF _condition="false">这段不输出</HY_IF>

<!-- 输出字面量 <HY_SITE_NAME> 用 \ 转义 -->
\<HY_SITE_NAME\> 显示原文
```

## 6. 完整示例

### 6.1 站点布局（site_layout.html）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>HY_SITE_NAME | <HY_SITE_SLOGAN _filter="default('无副标题')" /></title>
  <meta name="description" content="HY_SITE_DESCRIPTION">
  <meta name="keywords" content="HY_SITE_KEYWORDS">
  <link rel="icon" href="HY_SITE_FAVICON">
  <link rel="stylesheet" href="/assets/theme.css?v=HY_THEME_VERSION">
  <link rel="stylesheet" href="/assets/site.css?v=HY_BUILD_ID">
</head>
<body>
  <!-- ============ 头部 ============ -->
  <header class="site-header">
    <div class="container">
      <a href="HY_SITE_URL" class="logo">
        <img src="HY_SITE_LOGO" alt="HY_SITE_NAME">
        <span>HY_SITE_NAME</span>
      </a>
      <nav class="main-nav">
        <HY_SITE_MENU _location="header" />
      </nav>
    </div>
  </header>

  <!-- ============ 面包屑 ============ -->
  <nav class="breadcrumb container" aria-label="breadcrumb">
    <HY_BREADCRUMB />
  </nav>

  <!-- ============ 主内容（由栏目/详情布局填充）============ -->
  <main class="site-main">
    <HY_INCLUDE _file="main-content.html" />
  </main>

  <!-- ============ 页脚 ============ -->
  <footer class="site-footer">
    <div class="container">
      <nav class="footer-nav">
        <HY_SITE_MENU _location="footer" />
      </nav>
      <p class="copyright">
        <HY_SITE_COPYRIGHT /> · <a href="https://beian.miit.gov.cn/" target="_blank">HY_SITE_ICP</a>
      </p>
      <p class="build-info">Build #HY_BUILD_ID · Generated at HY_NOW</p>
    </div>
  </footer>
</body>
</html>
```

### 6.2 栏目布局（category_layout.html）—— 通用列表

```html
<HY_INCLUDE _file="site-header.html" />

<section class="category-page">
  <header class="cat-header">
    <h1>HY_CAT_NAME</h1>
    <HY_IF _condition="cat.has_description">
      <p class="cat-desc">HY_CAT_DESCRIPTION</p>
    </HY_IF>
  </header>

  <HY_IF _condition="cat.has_children">
    <aside class="sub-cats">
      <h3>子栏目</h3>
      <HY_CATS _type="children" _limit="20">
        <a href="HY_CAT_ITEM_URL" class="cat-chip">HY_CAT_ITEM_NAME</a>
      </HY_CATS>
    </aside>
  </HY_IF>

  <div class="content-list">
    <HY_CONTENTS _limit="20" _order="newest">
      <article class="post-card">
        <HY_IF _condition="item.has_cover">
          <a href="HY_ITEM_URL" class="cover">
            <img src="HY_ITEM_COVER" alt="HY_ITEM_TITLE" loading="lazy">
          </a>
        </HY_IF>
        <div class="post-body">
          <h2><a href="HY_ITEM_URL">HY_ITEM_TITLE</a></h2>
          <p class="summary"><HY_ITEM_SUMMARY _filter="truncate(100)" /></p>
          <footer class="post-meta">
            <time><HY_ITEM_DATE _filter="date('Y-m-d')" /></time>
            <span class="author">HY_ITEM_AUTHOR</span>
            <HY_IF _condition="item.has_tags">
              <span class="tags"><HY_ITEM_TAGS /></span>
            </HY_IF>
          </footer>
        </div>
      </article>
    </HY_CONTENTS>

    <HY_CONTENTS_EMPTY>
      <p class="empty">该栏目暂无内容</p>
    </HY_CONTENTS_EMPTY>
  </div>

  <nav class="pagination">
    <HY_CONTENTS_PAGINATION />
  </nav>
</section>

<HY_INCLUDE _file="site-footer.html" />
```

### 6.3 详情布局（content_layout.html）

```html
<HY_INCLUDE _file="site-header.html" />

<article class="post">
  <header class="post-header">
    <h1>HY_CONTENT_TITLE</h1>
    <div class="post-meta">
```

### 7.1 `layouts` 布局模板表

```sql
CREATE TABLE layouts (
  id              BIGSERIAL PRIMARY KEY,
  site_id         BIGINT NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  scope           VARCHAR(20) NOT NULL,        -- site | category | content | home
  code            VARCHAR(64) NOT NULL,        -- 唯一编码: default | magazine | minimal
  name            VARCHAR(128) NOT NULL,        -- 中文名

  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  UNIQUE(site_id, scope, code)

CREATE INDEX idx_layouts_site_scope ON layouts(site_id, scope) WHERE deleted_at IS NULL;
```

**scope 枚举**：
- `site` —— 站点公共布局（1 个 default，公共 header/footer 写在 site_layout 里）

- `content` —— 内容详情布局（按 `contents.template` 字段匹配）
- `home` —— 站点首页布局（**特殊栏目**，slug="home" 或单独一个）

### 7.5 网站 ZIP 导入时的模板数量（产品约定）

> **一个栏目 = 一套列表模板 + 一套详情模板**，同栏目下所有页面共用，**不会**为每个 HTML 各建一份。

| 规则 | 说明 |
|---|---|
| 栏目分组 | 子目录名（`news/foo.html` → 栏目 `news`）；根目录文件取文件名前缀（`news-bid.html` → 栏目 `news`） |
| 列表模板 | `scope=category`，`code` = 分组名（如 `news`），该栏目下所有列表页共用 |
| 详情模板 | `scope=content`，`code` = 分组名（如 `news`），该栏目下所有详情页共用 |
| 整站 ZIP | 另含 `default` 六件套（site/home/category/content + header/footer）；各分组再各增 1 列表 + 1 详情 |
| 二级 ZIP | 只新增尚未存在的分组模板，不覆盖已有 `default` / header / footer |

示例：「新闻资讯」栏目绑定 `category` 模板 code=`news`、文章绑定 `content` 模板 code=`news`；20 篇新闻仍只有这一套模板，正文差异来自 CMS 内容与 `HY_CONTENT_*` 标签。

## 8. 渲染管线（SSG 阶段）

```
1. 触发发布 (publish_jobs)
   ↓
2. Worker 拉取：sites / layouts / taxonomies / contents
   ↓
3. 对每个输出页面：
   ┌──────────────────────────────────────────────┐
   │ 选模板：                                        │
   │   - 首页 → layouts WHERE scope='home'          │
   │   - /cat/foo/ → layouts WHERE scope='category' │
   │              AND code = cat.template            │
   │   - /p/123.html → layouts WHERE scope='content'│
   │              AND code = content.template       │
   │                                                │
   │ 包裹 site_layout：                               │
   │   site_layout.html 包裹 [选中的页面布局].html   │
   │   <main>HY_INCLUDE 位置</main>                 │
   └──────────────────────────────────────────────┘
   ↓
4. 解析 HTML 中的 HY_ 标签：
   a. 单值标签（HY_SITE_NAME 等）→ 直接字符串替换
   b. 容器标签（HY_CONTENTS ... /HY_CONTENTS）→ 循环渲染
   c. 条件标签（HY_IF ... /HY_IF）→ 按条件裁剪
   d. 包含标签（HY_INCLUDE file="x"）→ 读文件 + 递归解析
   ↓
5. 写入 /sites/<slug>/dist/index.html .../cat/foo/index.html .../p/123.html
   ↓
6. 上传 publish_history
```

### 8.1 解析器伪代码

```python
# backend/app/services/layout_renderer.py
import re
from pathlib import Path

class LayoutRenderer:
    def __init__(self, context: RenderContext):
        self.ctx = context  # site / cat / content / list 等

    def render(self, html: str) -> str:
        # 1) 解析 HY_INCLUDE
        html = self._resolve_includes(html)
        # 2) 解析 HY_IF
        html = self._resolve_ifs(html)
        # 3) 解析循环标签 HY_CONTENTS ... /HY_CONTENTS
        html = self._resolve_loops(html)
        # 4) 解析自闭合单值标签 <HY_xxx />
        html = self._resolve_self_closing(html)
        # 5) 解析文本中的 HY_xxx
        html = self._resolve_inline(html)
        # 6) 应用 filter
        html = self._apply_filters(html)
        return html

    def _resolve_loops(self, html: str) -> str:
        # 匹配 <HY_CONTENTS _limit="10">...</HY_CONTENTS>
        # 或 <HY_CATS _type="children">...</HY_CATS>
        pattern = re.compile(
            r'<HY_(CONTENTS|CATS)([^>]*)>(.*?)</HY_\1>',
            re.DOTALL | re.IGNORECASE
        )
        def repl(m):
            tag = m.group(1).upper()   # CONTENTS | CATS
            attrs = parse_attrs(m.group(2))  # _limit / _order / _cat / _type
            inner = m.group(3)
            items = (self.ctx.query_contents(attrs) if tag == 'CONTENTS'
                     else self.ctx.query_cats(attrs))
            return ''.join(
                self.render_with_item(inner, item)  # 递归解析 + 注入 item
                for item in items
            )
        return pattern.sub(repl, html)
```

## 12. 与现有系统的对接

### 12.1 核心关系：1 模板 ↔ N 主题（解耦）

> **Layout（结构骨架）**与 **Theme（视觉风格）**是两个独立维度，通过 **Token 系统**接驳。

```
┌──────────────────────────────────────────────────────────────┐
│  1 个 Layout（结构）  ←→  N 个 Theme（视觉）                  │
│                                                              │
│  layout.html:                                                │
│    <h1 class="text-primary">HY_SITE_NAME</h1>                │
│    <button class="btn-primary">订阅</button>                  │
│                                                              │
│  主题 A（蓝）:    --color-primary: #2563eb                    │
│  主题 B（红）:    --color-primary: #dc2626                    │
│  主题 C（暗）:    --color-primary: #facc15                    │
│                                                              │
│  → 同一 layout × 3 主题 = 3 种外观，1 份 HTML                │
└──────────────────────────────────────────────────────────────┘
```

**铁律**：
- ✅ Layout 里**只用 token 类名**（`text-primary` / `btn-primary` / `bg-surface`）
- ❌ Layout 里**禁止写 hex/字号/px**（`color: #2563eb` / `font-size: 16px`）
- ❌ Layout 里**禁止 import 主题 CSS**（CSS 引用由主题决定，不在 layout 里）

### 12.2 各系统对接

| 系统 | 怎么对接 |
|---|---|
| **主题 (themes)** | theme 输出 token CSS 变量，layout 不感知主题存在。**主题切换 = 自动换肤** |
| **Block (Tiptap)** | layout 里 `<HY_CONTENT_BODY />` 输出编译后的 Block HTML。Block 内的 token 类名走主题 |
| **菜单 (menus)** | `<HY_SITE_MENU _location="header" />` 输出 menus.items 渲染的 HTML（ul/li + token 类名）|
| **栏目 (taxonomies)** | 栏目列表页 = scope='category' 的 layout + 当前栏目 context |
| **媒体 (media)** | `<HY_ITEM_COVER />` 直接拿 contents.cover_media_id 解析的 URL |
| **AI** | AI 改 layout = 自然语言 → 改 HTML（受 schema 约束，可回滚），**V2 做** |

### 12.3 主题切换 = 0 改动

```
用户在后台切主题（蓝→红）：
   1. site.current_theme_id 改值
   2. 重新触发 SSG（增量）
   3. layout.html 不动（仍是同一份 HTML）
   4. theme.css 重生成（token 值变了）
   5. 产物外观从蓝变红，**HTML 结构 100% 不变**
```

### 12.4 例外场景（V2 处理）

- **首页 hero 想做"杂志大图"** vs **"极简文字"** → 这是**结构差异**不是样式差异
- **方案**：layout 提供 `<HY_SLOT name="hero" />`，主题可在 theme 包内提供**默认 slot HTML**（V2 做）
- v0.1 不支持，5 主题共用同一套 layout 结构

## 14. 风险 & 缓解

| 风险 | 缓解 |
|---|---|
| 标签解析 XSS | 所有数据走 `html.escape()`，富文本字段显式标记 `safe=True` |
| 循环标签性能（1000+ 条） | SSG 阶段单次解析，零运行时；构建时分页默认 20/页 |
| 模板写错导致发布失败 | 渲染前 `validate()` 校验，错误信息精确到行号 |
| 用户写 `<script>` | v0.1 黑名单过滤 + 构建时 lint 警告 |
| 主题切换后 layout 样式错乱 | layout 只用 token 类名（`text-primary`），不写 hex |
| HY_ 标签属性被 HTML 解析吃掉 | 业务属性全部 `_` 前缀（`class` / `id` / `style` 走 HTML 原生） |
| 嵌套循环复杂度 | v0.1 **不支持嵌套**（HY_CONTENTS / HY_CATS 不可互相嵌套），v2 再开 |

## 15. FAQ

**Q1. 为什么不用现成模板引擎（jinja2/liquid）？**
A: 38 个标签 = 闭包可控，200 行 Python 即可。jinja2 灵活但 XSS 风险大、性能损耗、对前端/AI 都不友好。

**Q2. 为什么 HTML 里有 `<HY_xxx />` 这种 XML 自闭合？**
A: 让 HTML 能被浏览器/CodeMirror 正常解析，又能被我们的 regex 识别。`<HY_xxx>value</HY_xxx>` 也支持（去掉 HTML 标签即可）。

**Q3. AI 怎么改布局？**
A: V2 再说。V1 用户手写 HTML（CodeMirror 高亮）。AI 改 = 自然语言 → diff 预览 → 用户确认。

**Q4. 一篇文章能套不同 layout 吗？**
A: 可以。`contents.template` 字段决定。同一站点有 `default` / `wide` / `minimal` 3 套，编辑时选。

**Q5. 子栏目页能"继承"父栏目布局吗？**
A: **不继承**。`template` 默认 `default`，空 = 用站点默认。想继承父栏目 = 复制 template 字段。

**Q6. 性能：1 万篇文章要多久发布？**
A: SSG 阶段单次解析，每页 1-50ms。1 万页 = 5-15 分钟。后续做增量（内容/布局未变 → 跳过）。

## 2. P5 修复

### 2.1 `UserLogin.password` 加 `min_length=8` (后端)

**文件**: `backend/app/schemas/user.py:38-42`

**动机**: 之前 UserLogin 没 min_length 校验，短密码（但非空）会落到 `verify_password` 走 False 分支返 `40105`，与"密码格式错"语义混淆。

**修法**: 加 `Field(min_length=8, max_length=128)`，与 `UserCreate` 一致。

**验证**: P5 e2e §1.3 第 2 行。

### 2.2 删 `docker-compose.dev.yml` (4 行空架)

**文件**: 删 `deploy/docker-compose.dev.yml`

**动机**: P0 留下的"未来要用的覆盖"占位文件，4 行全注释，实际 `version: "3.9"` 还触发废弃警告。**6 个月没用 = 该删**。

### 2.3 删 `docker-compose*.yml` 的 `version:` 字段

**文件**: `deploy/docker-compose.yml:5`

**动机**: Compose V2 弃用 `version` 字段，启动时打 "the attribute `version` is obsolete" 警告。删一行干净。

**验证**: `docker compose config` 解析无警告。

### 2.4 `nginx.rebuild_sites_map` 同步 IO 隔离 (尝试)

**文件**: `backend/app/core/nginx.py:65-80`

**动机**: 启动日志 "greenlet_spawn has not been called; can't call await_only() here" 警告。

**修法**: 把 `with open(...)` `os.replace(...)` 包到 `asyncio.to_thread` 里。

**结果**: 警告**仍然出现**（P0/P2.5 留的问题，nginx map 写失败被 catch 成 "non-fatal" 符合预期——api 容器内 `/etc/nginx/conf.d/` 不存在，写本地 fallback 也未必成功，但 nginx 容器自己用 inotify 监听 mount 内的变化）。**实际不影响**。已记为"P2.5 遗留，不修"。

## 4. 决策记录 (供后续)

1. **MOCK 兜底**: 启动流改写时若 user 没配 provider, 走默认 ollama 路径; ollama 无模型 (probe) 时降级 Mock。**这是 P3.0 决策 #1**，对 demo 和 dev 必要。
2. **AI 入口位置**: P3.6 选了"侧边栏 AI 分组 + ContentDetail 按钮"双入口。P4 之前只有侧边栏，ContentDetail 是真用 AI 的场景，单独加。
3. **SSE 用 fetch + ReadableStream**: 因为要 Bearer 头，EventSource 不支持。包装在 `frontend/src/api/ai.ts:streamRun`。
4. **不引 UI 库**: Drawer 用原生 `<dialog>` + CSS 关键帧。P0 决策"轻量"延续。
5. **Pydantic 422 vs 业务码**: 422 是 Pydantic schema 验证（HTTP 标准），业务码（40105 等）是约定俗成的细粒度。两者并存，HTTP 状态码正确即可。

# 10 · 权限矩阵（RBAC）

> **P1 启动前必读**。完整角色 × 操作权限矩阵。后端 API 和前端 UI 都要遵守。

---

## 0. 角色定义

| 角色 | 英文 | 范围 | 数量 |
|---|---|---|---|
| 超级管理员 | super_admin | 全平台, 跨站 | 1-N |
| 站点所有者 | owner | 单站 | 1 个/站 |
| 站点编辑 | editor | 单站 | 0-N 个/站 |
| 站点查看者 | viewer | 单站 | 0-N 个/站 |

---

## 1. 角色继承关系

```
super_admin (跨站, 最高权限)
    └─ owner (单站, 站点内所有权限)
        └─ editor (单站, 编辑权限)
            └─ viewer (单站, 只读)
```

**注意**：
- `super_admin` 自动拥有所有站点的 owner 权限（应用层判断）
- `owner` 不能跨站（除非也是 super_admin）
- 角色**不可继承**（owner 不能创建 owner）

## 3. 特殊规则

### 3.1 协作锁

- 编辑内容时**强制加锁** 5 分钟
- 第二个用户进入编辑页 → **只读** + 显示 "X 正在编辑 (3 分钟前)"
- 锁过期后第二个用户**可接管**（提示 "锁已过期，是否接管？"）
- 关闭浏览器 30 秒后**自动释放**（前端心跳）

### 3.2 资源所有权

- editor 创建的内容，**初始作者 = 自己**
- editor 只能**编辑/删除自己的内容**
- owner 可编辑/删除**站内任何人的内容**
- super_admin 可跨站编辑

### 3.3 删除限制

- editor 不能删除任何内容（仅软删除自己的"草稿"）
- owner 可删除站内任何内容
- 软删除 → 回收站 → 30 天后 Celery 清理

### 3.4 转让所有权

- owner 想离开站点 → 必须先**指定新 owner**
- 新 owner 必须是站点现有成员
- 转让后原 owner 降级为 editor

## 4. API 端点权限（实现示例）

```python
# backend/app/core/permissions.py
from enum import Enum
from functools import wraps

class Action(str, Enum):
    SITE_CREATE = "site:create"
    SITE_EDIT = "site:edit"
    SITE_DELETE = "site:delete"
    CONTENT_CREATE = "content:create"
    CONTENT_EDIT_OWN = "content:edit:own"
    CONTENT_EDIT_ANY = "content:edit:any"
    CONTENT_DELETE = "content:delete"
    CONTENT_PUBLISH = "content:publish"
    THEME_AI_MODIFY = "theme:ai_modify"
    # ... 全部操作

PERMISSIONS = {
    "super_admin": [a for a in Action],  # 所有
    "owner": [
        Action.SITE_EDIT, Action.SITE_DELETE,
        Action.CONTENT_CREATE, Action.CONTENT_EDIT_OWN, Action.CONTENT_EDIT_ANY,
        Action.CONTENT_DELETE, Action.CONTENT_PUBLISH,
        Action.THEME_AI_MODIFY,
        # ...
    ],
    "editor": [
        Action.CONTENT_CREATE, Action.CONTENT_EDIT_OWN,
        Action.THEME_AI_MODIFY,  # 自己的 AI Key
        # ...
    ],
    "viewer": [],
}

def require_permission(action: Action):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            # 从 kwargs 取 user, resource
            user = kwargs.get("user") or args[0]
            # 检查 user.permissions
            if not user.has_permission(action):
                raise PermissionDenied(action)
            return await func(*args, **kwargs)
        return wrapper
    return decorator
```

## 5. 前端 UI 显隐规则

### 5.1 显隐原则

- **没有权限的按钮不显示**（不是显示后禁用）
- 例外：批量操作时**禁用**而不是隐藏（避免界面跳动）
- 没有权限的页面 → **403 页**（不是空页）

### 5.2 实现

```tsx
// src/components/auth/Can.tsx
import { useAuthStore } from '@/stores/auth';

export function Can({ action, children, fallback = null }: {
  action: Action;
  children: React.ReactNode;
  fallback?: React.ReactNode;
}) {
  const user = useAuthStore(s => s.user);
  if (!user) return fallback;
  if (user.is_super_admin) return children;
  // 站点级角色判断
  const siteRole = useCurrentSiteRole();  // 当前站点的角色
  if (hasPermission(siteRole, action)) return children;
  return fallback;
}

// 用法:
<Can action={Action.CONTENT_DELETE}>
  <Button>删除</Button>
</Can>
```

## 6. 权限缓存

- 用户权限在登录时计算，存 Redis
- 用户角色变化时**主动失效**
- Token 刷新时重新计算
- 缓存 key: `user:{id}:perms`

## 7. 审计要求

**所有权限拒绝都要记录**：

# audit_logs 表

changes = {"required": "content:delete", "user_role": "editor"}

## 8. 边界情况

| 场景 | 行为 |
|---|---|
| 站点有 1 个 owner, owner 离职 | 必须先转让, 否则站点无主 |
| 用户被从站点移除 | 立即失效其该站所有 token (JWT 黑名单) |
| 站点被归档 | 所有成员保留, 但站点不可写 |
| 站点被删除（软删除）| 30 天可恢复, 30 天后硬删除 |
| 用户被硬删除 | 其创建的内容**不删除**（`author_id` 改为 `NULL` 或保留 ghost 用户）|
| AI 改主题被拒（超出白名单）| 不写入, 返回 422 + 详细错误 |
| 跨站操作（editor 想看别的站）| API 404（不是 403, 不暴露存在性）|

## 9. 权限矩阵变更流程

1. 任何权限变更先**改本文档**
2. 后端代码 `permissions.py` 必须与本文档**一致**（测试覆盖）
3. 前端 `Can` 组件必须与本文档**一致**
4. 变更需要 super admin 确认（双人复核）

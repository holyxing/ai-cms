## 关键设计选择 (供后续参考)

### 1. MockProvider 降级
- 健康检查 2s 超时,失败自动 mock
- 让开发/演示不被网络阻塞
- P3.1+ 加环境变量 `AI_FORCE_MOCK=1` 强制 mock (集成测试用)

### 2. AIProvider 配置 per-user
- 不全局硬编码,允许多 provider (openai + ollama 并存)
- `is_default=true` 唯一 (应用层保证)
- P3.1+ 加 Fernet 加密 api_key

### 3. 4 步状态机 (validate → generate → sanitize → save)
- 每步独立 ai_run_step 行,可重试单个步骤
- 流式 delta 写在 `generate` 步的 `delta` 字段
- P3.3+ audit 会扩展为 5 步 (加 compliance_check)

### 4. SSE 简化版 (1s 轮询)
- 不用 redis pubsub,前端简单 fetch+ReadableStream
- 最多 2min 超时,真实 AI 任务一般 5-30s
- P3.1+ 改 pubsub (同时多客户端订阅)

### 5. accept 流程: 写新 version_num (不覆盖)
- 用户可"接受/拒绝"
- 接受 → content_versions 新一行 (version_num+1)
- 拒绝 → run 状态改 cancelled, version 不动
- P3.1+ 加 `/ai/runs/{id}/reject` 端点

### 6. content_versions 模型与 09 文档不一致
- 09 文档: body_json + body_html + body_text 三列
- 实际 P1 实现: 只有 body (Text) + excerpt
- 决策: 接受现状, accept 端点用 markdown 简单 wrap
- P3.1+ 如需富文本,迁移时再加列

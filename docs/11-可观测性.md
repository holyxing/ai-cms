## 1. 日志（Logs）

### 1.1 结构化日志（**强制**）

```python
# backend/app/core/logging.py
import structlog

log = structlog.get_logger()

# 严禁: print("user logged in")
# 强制:
log.info("user_logged_in", user_id=123, ip="1.2.3.4", duration_ms=45)
```

**字段约定**：
- 时间戳 (ISO 8601 UTC)
- level (debug/info/warn/error)
- event (snake_case 名词短语)
- user_id / site_id / request_id
- 业务字段（如 content_id）
- duration_ms

### 1.2 必记日志事件

| 事件 | 字段 |
|---|---|
| `auth.login.success` | user_id, ip, user_agent |
| `auth.login.failed` | email, ip, reason |
| `auth.logout` | user_id |
| `site.created` | site_id, user_id, slug |
| `site.deleted` | site_id, user_id |
| `content.created` | content_id, site_id, user_id |
| `content.published` | content_id, version, user_id |
| `media.uploaded` | media_id, size, mime, user_id |
| `theme.ai_modified` | site_id, theme_version_id, cost_usd |
| `ai.run.started` | run_id, task_type, user_id |
| `ai.run.failed` | run_id, error |
| `permission.denied` | user_id, action, resource |
| `deployment.started` | deployment_id, site_id |
| `deployment.failed` | deployment_id, error |

### 1.3 日志输出

- **开发环境**：stdout（容器日志）
- **生产环境**：写文件 → Filebeat → Elasticsearch
- **本机部署（用户场景）**：写 `/data/logs/{service}.log` + 日志轮转（logrotate）

### 1.4 请求日志中间件

```python
@app.middleware("http")
async def log_requests(request, call_next):
    start = time.time()
    request_id = str(uuid4())

    response = await call_next(request)
    duration = (time.time() - start) * 1000

    log.info(
        "http_request",
        request_id=request_id,
        method=request.method,
        path=request.url.path,
        status=response.status_code,
        duration_ms=round(duration, 2),
        user_id=getattr(request.state, "user_id", None),
        ip=request.client.host,
    )
    response.headers["X-Request-ID"] = request_id
    return response
```

**慢请求告警**：`duration_ms > 1000` 自动 warn。

from prometheus_client import Counter, Histogram, Gauge

### 3.2 慢查询追踪

```python
# backend/app/db/events.py
from sqlalchemy import event

@event.listens_for(Engine, "before_cursor_execute")
def receive_before_cursor_execute(conn, cursor, statement, parameters, context, executemany):
    context._query_start_time = time.time()

@event.listens_for(Engine, "after_cursor_execute")
def receive_after_cursor_execute(conn, cursor, statement, parameters, context, executemany):
    total = (time.time() - context._query_start_time) * 1000
    if total > 100:  # 慢查询
        log.warning("slow_query", duration_ms=total, statement=statement[:200])
```

@app.get("/healthz")
async def healthz():
    """Liveness - 进程活着"""

async def readyz():
    """Readiness - 可服务"""
    checks = {
        "db": await check_db(),
        "redis": await check_redis(),
        "minio": await check_minio(),

## 6. 告警

### 6.1 告警渠道

P1-P3 **本机部署**，用最简方案：
- **邮件**（推荐 SMTP, 关键告警）
- **Telegram Bot**（开发环境）
- **不接入 PagerDuty / OpsGenie**（用户用不到）

### 6.2 告警规则

| 指标 | 阈值 | 告警级别 |
|---|---|---|
| API 5xx 错误率 | >5% (5 分钟) | error |
| API P95 响应时间 | >2s (5 分钟) | warning |
| DB 连接数 | >80% pool | warning |
| 磁盘使用 | >85% | error |
| 内存使用 | >90% | error |
| Celery 任务积压 | >100 个 (5 分钟) | warning |
| AI 任务失败率 | >20% (1 小时) | warning |
| 容器重启 | 1 分钟内 >1 次 | error |
| 备份失败 | 1 次 | error |
| Sentry 错误爆发 | 1 小时 >50 个 | error |

### 6.3 告警内容

```python
def send_alert(level, title, details):
    message = f"""
[{level.upper()}] {title}

时间: {datetime.now(UTC).isoformat()}
详情: {details}

服务器: {settings.HOSTNAME}
环境: {settings.ENV}
"""
    send_email(settings.ALERT_EMAIL, f"[AI-CMS {level}] {title}", message)
```

### 6.4 告警去重

- 同类告警 5 分钟内**只发一次**
- 恢复时发"resolved"消息
- 实现：Redis `ALERT:KEY` TTL 5 分钟

### 11.1 核心指标

| 指标 | 来源 | 告警阈值 | 备注 |
|---|---|---|---|

| `celery_cross_loop_errors` | 日志 grep `got Future.*different loop` | > 0/小时 | 引擎 dispose 失效 |

### 11.2 端到端验证 (Day 6 验证)

```bash
# 触发一次发布
curl -X POST http://localhost:18888/api/v1/sites/$SITE_ID/publish

# 轮询状态 (前端 Publish.tsx 用了相同模式)
for i in 1 2 3 4 5; do
  STATUS=$(curl -s -H "Authorization: Bearer $TOKEN" \
    http://localhost:18888/api/v1/publish/jobs/$JOB_ID | jq -r .data.status)
  echo "poll $i: $STATUS"
  [ "$STATUS" = "success" ] || [ "$STATUS" = "failed" ] && break
  sleep 2
done

# 验证产物可访问
curl -I http://localhost/sites/{slug}/
curl -I http://localhost/sites/{slug}/previews/{theme}.svg
```

### 11.3 已知 P2 故障模式

| 现象 | 根因 | 修复 |
|---|---|---|
| publish 一直 pending | Celery cross-loop (engine 绑了旧 loop) | `_run_with_loop` 加 `await engine.dispose()` |
| publish failed `Permission denied: /var/www/sites` | appuser 没写权 | Dockerfile chown /var/www 给 appuser |
| publish 200 但 /sites/{slug}/ 403 | 文件 600 nginx 读不到 | publish.py chmod 644 / 755 |
| npm install 卡 5min+ | docker hub 网络不稳 | 改用 npmmirror.com (11s 装 331 packages) |
| 真构建 dist 里没 public/ | Astro 把 public/ 内容合并到 dist/ 根 | 不需要修, 预期行为 |

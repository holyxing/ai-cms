# 21. AI 助手整合重构 (P3.10 — 站点 AI / 文章 AI / 模板 AI 合 1)

> **v1.0 · 2026-06-13 · holy 反馈 #12875**
>
> 把站点 AI、文章 AI、模板 AI 三套独立入口整合成 **1 个全局浮动 AI 助手**，根据当前页面路由 + 页面注入的 Context 智能切换能力。

---

## 1. 现状与痛点

### 1.1 当前 3 套入口

| 入口 | 组件 | 触发位置 | 任务集 | UI 形态 | 代码量 |
|------|------|----------|--------|---------|--------|
| **文章 AI** | `AIChatPopup` + `AIChatPanel` (907行) | 顶 nav "AI" 按钮 | article 模式：改写/扩写/缩写/润色/翻译/起稿/审计/配图/import_docx/pdf/paste | 居中浮窗 (max-w-2xl) | 907 |
| **站点 AI** | `SiteAIDrawer` + `SiteAIPanel` (607行) | Dashboard 右下角浮动紫粉按钮 | site_agent 通用对话 | 右侧抽屉 (侧栏 480px) | 607 |
| **模板 AI** | `AIThemeDialog` (343行) + LayoutEditPage 内 4 任务 | LayoutEditPage 顶部 AI 按钮 | theme / optimize_design / responsive / a11y / seo | 居中 Modal (max-w-2xl) | 343 |

外加 v1 残骸 `AIDrawer.tsx` (250行) / `AIChatDrawer.tsx` (110行) / `AITaskPicker.tsx` (59行) — 没人用。

### 1.2 三大痛点

1. **入口混乱** — 顶 nav 一个 AI 按钮（弹文章 AI 浮窗），Dashboard 右下角又一个浮动按钮（弹站点 AI 抽屉），进 LayoutEditPage 又是第 3 个 AI 按钮（弹模板 AI Modal）。用户在不同页看不到统一入口。
2. **代码重复** — `AIChatPanel` (907) + `SiteAIPanel` (607) 重复实现 chat UI（消息列表 / 流式 / abort / 滚动）。3 套各自的 `messages` / `abortRef` / 流式订阅互不通用。
3. **上下文断层** — 文章 AI 看得到 `useEditorStore.body/html`，模板 AI 看得到 `useEditorStore.html`，站点 AI 看得到 sites_context — 三套各自 fetch 上下文，**没有统一的"当前 AI 应该看什么"机制**。

---

## 2. 目标 (3 个)

1. **1 个全局 AI 助手** — 全站所有页面共用一个浮动入口（位置 right-6 bottom-6，紫粉球 icon 同 SiteAIFloatButton）
2. **1 套核心代码** — 删 v1 残骸 + 删 3 套 chat UI 重复，统一在 `AIAssistant` + `AIAssistantPanel` 里
3. **按上下文智能切换能力** — 进文章页自动显示文章任务，进模板页自动显示模板任务，进 Dashboard 显示通用对话

## 3. 决策 (Q1-Q5)

### Q1 · AI 入口统一形态

**A — 全局浮动 AI 助手**（已选）
- 全站共享一个浮动按钮，位置 `fixed right-6 bottom-6`，紫粉渐变球（同 SiteAIFloatButton 风格）
- 点击后弹出居中 Modal（**不是右侧抽屉**），Modal 风格参考 `AIThemeDialog`（max-w-2xl，输入区+上下文预览+任务列表+流式输出+底部操作）
- 顶 nav 现有 "AI" 按钮 → 删除（避免双入口）
- Dashboard 现有 `SiteAIFloatButton` → 替换成新的 `AIAssistantFloatButton`

> 选 A 的原因：跟当前 SiteAIFloatButton 已经接近，扩展"全局 + 按页面切"最自然；抽屉式（侧栏 480px）放 chat 太窄，放 diff 太挤，居中 Modal 跟模板 AI 一致用户已经习惯

### Q2 · 上下文识别

**C — Hybrid**（已选）
- **默认基于 URL 路由**（A 方案）：`/admin/sites/:id/layouts/:id` → template 模式；`/admin/sites/:id/contents/:id` → article 模式；`/admin` 或 `/admin/c/:id` → general 模式
- **特殊页面可注入 override**（B 方案）：通过 `useAIContext().setContext({type, target, payload})` 显式指定（如 ContentDetail 注入 `content_body` 跟 `content_id`，LayoutEditPage 注入 `layout_html` 跟 `tokens`）
- 95% 页面 A 够用，复杂页面 C-B 注入更精确

### Q3 · 上下文传递

**C — 混合**（已选）
- **AI 助手弹起时自动嗅探**（A 方案）：从 `useEditorStore` / `useParams` / 当前 tab store 读 `{text, target, resourceId, siteId}`
- **用户在弹窗内可 override**（B 方案的轻量版）：弹窗内有个"上下文"折叠区，显示当前自动嗅探的内容，用户可手动调整"应用到其他位置"或"重新选择文本"
- 类似 Vercel v0 / Cursor Tab 的"自动 + 手动"双轨

### Q4 · 旧组件处理

**C — 彻底整合**（已选）
- 删除 v1 残骸：`AIDrawer.tsx` / `AIChatDrawer.tsx` / `AITaskPicker.tsx` (合计 419 行)
- 替换 3 入口为 1：`AIChatPopup` / `AIChatPanel` / `SiteAIDrawer` / `SiteAIPanel` / `AIThemeDialog` → 全部删除
- 保留 AI 后端 18 个 `task_type` 不变（这是后端契约，不动）
- 一次性整合，**不留过渡债**（跟 holy 风格一致）

### Q5 · 文档

**A — 新建 `docs/21-AI助手整合重构.md`**（已选，即本文）

### 4.2 状态管理 (aiAssistant store)

```ts
// stores/aiAssistant.ts
type AIMode = 'article' | 'template' | 'general';

interface AIAssistantState {
  open: boolean;                  // 弹窗开关
  mode: AIMode;                   // 当前模式 (auto from URL, 可手动切换)
  context: AIContext | null;      // 注入的上下文 (Q2C)
  conversationId: string | null;  // site_agent 多轮用
  messages: ChatMessage[];        // 统一消息列表
  // actions
  open: (mode?: AIMode) => void;
  close: () => void;
  toggle: () => void;
  setMode: (mode: AIMode) => void;
  setContext: (ctx: AIContext) => void;
  send: (text: string, task?: AITaskType) => Promise<void>;
  abort: () => void;
  accept: (msgId: string) => Promise<void>;
  reject: (msgId: string) => Promise<void>;
}
```

### 4.3 路由 → 模式自动映射 (Q2 默认)

```ts
// aiContext.ts
function inferModeFromPath(pathname: string): AIMode {
  if (pathname.match(/^\/sites\/[^/]+\/contents\/[^/]+$/)) return 'article';
  if (pathname.match(/^\/sites\/[^/]+\/layouts\/[^/]+$/)) return 'template';
  return 'general';
}
```

特殊页面用 `setContext` override：

```ts
// ContentDetail.tsx
useEffect(() => {
  useAIAssistant.getState().setContext({
    type: 'article',
    target: { contentId, siteId, title, slug },
    payload: { body: content.body, html: content.html, excerpt: content.excerpt },
  });
}, [contentId, body, html]);

// LayoutEditPage.tsx
useEffect(() => {
  useAIAssistant.getState().setContext({
    type: 'template',
    target: { layoutId, siteId, name },
    payload: { html: layout.html, tokens: layout.tokens, designLang },
  });
}, [layoutId, html, tokens]);
```

## 12. D3 反馈记录 (P3.10 实施)

### 12.1 store.send() payload 错位 (修复)
- **坑**: 原 store.send() 拼 payload 是 `{original_text, html, user_input, ...}` 平铺; 但后端 schema 是 `{site_id, content_id, layout_id, input, design_lang}` 顶层 + `input: {...}` 嵌套
- **修**: 把所有 task-specific 字段塞进 `input: {...}` 嵌套, 顶层只放 schema 字段 (site_id/content_id/layout_id/design_lang)
- **注意 audit 任务用 `text` 字段, text_transform 7 任务用 `original_text`** — 两个都传避免漏
- **预防**: **永远后端 AITaskStart 嵌套 input, 不要平铺 payload**

### 12.2 SSE 终态检测 (修复)
- **坑**: 后端 SSE 用 `event: message` (默认) 发送 status/output/error, 不是显式 `event: output` 或 `event: done`. 原 store 检查 `if (ev.event === 'output' || ev.event === 'done')` 永远不命中, state 永远 `running`
- **修**: 改用 `if (d.status === 'success' || d.status === 'failed' || d.status === 'cancelled')` 检测终态, 不依赖 ev.event
- **预防**: **永远 SSE 事件用 data.status 字段判断终态, 不要依赖 ev.event 名**

1. **浮球 z-40 + backdrop z-40 同 z-index**: 浮球在 DOM 前, backdrop 在 DOM 后 → 浮球被 backdrop 遮挡 → 浮球点 2 时浏览器把 click 当 backdrop 的 click → 触发 backdrop.close()
2. **Native dialog useEffect 同步 onClose 链路不稳**: P3.10.7 用 `<dialog>` + `dlg.showModal()/close()` useEffect 同步, holy 实测"AI 无法关闭" (Playwright 直接调 toggle 没事, 但浮球二次点击 onClick 没触发)
3. **抽屉 onKeyDown 依赖聚焦**: Esc 只在抽屉有焦点时触发, 实际打开后 active element 是浮球, Esc 无效

**修法** (3 处):
1. `AIAssistantPanel.tsx`: 改用普通 div 容器 (不依赖 native dialog)
   - backdrop 改独立 `<div fixed inset-0 z-40 bg-black/30 onClick={close}>` (open 时显示)
   - 抽屉本体 `div fixed right-0 z-50 h-screen w-[420px]` + `style="display: open ? 'flex' : 'none'"`
   - 删 dialogRef + useEffect 同步
2. `AIAssistantPanel.tsx`: 加全局 `document.addEventListener('keydown', Esc→close)` useEffect (open 时挂, 关闭时清)
3. `AIAssistant.tsx`: 浮球 `z-40 → z-[60]`, 确保浮球总在最上 (抽屉打开时也点得到, 不会被 backdrop 遮挡)

**E2E 验证 6/6 + 0 page errors**:
- T1 X 按钮关闭 / T2 Esc 关闭 (全局 keydown) / T3 点 backdrop 关闭 / T4 浮球再点关闭 (z-60 修好) / T5 抽屉贴右 right gap=0 / T6 抽屉满屏 height=900

### 预防条目 (P3.10.11-P3.10.12 累计)

- **永远多关闭路径要 3 个** (浮球 + Esc + backdrop), 不要 4 个 (加 X 按钮冗余)
- **永远浮球 inX mode 复用**: open=true 时浮球 icon 变 X, 提供"视觉上理解成关"的体验, 不需要额外 X 按钮
- **永远 2 关闭路径功能重复时删一个**: 用户反馈"这个图标根本不需要" 通常是因为已有等价方案
- **永远看截图先识别反馈指向哪个具体元素**: holy 反馈截图时, 仔细看 tooltip/aria-label/text 定位到具体元素, 避免改错
- **永远抽屉内的元素位置 vs 全局浮球位置要算坐标**: 浮球 (1380, 840) vs 抽屉内"发送" (1038, 60 + scroll?) → 浮球始终 fixed 不动, 抽屉内任何底部元素都有冲突风险
- **永远抽屉打开时全局浮球应隐藏**: 抽屉本身就是"主交互面", 浮球作为辅助入口在抽屉打开时没必要
- **永远看反馈要回溯到原话**: holy 反馈 #13507 原话"icon 可以隐藏", 不是"变 X 图标", 之前 P3.10.11 我误读成 inX mode 导致二次返工 (删错按钮)
- **永远 z-index 高 = 浮起来遮挡, 不代表"不挡"**: z-60 浮球 + z-50 抽屉 = 浮球挡住抽屉底部元素, 仍是遮挡
